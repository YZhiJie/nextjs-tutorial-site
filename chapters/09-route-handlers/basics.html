当你需要一个「真正的 HTTP 端点」 ​

Server Actions 覆盖了表单变更，但有些能力天然属于裸 HTTP 端点：给第三方系统的 Webhook 回调、给移动端/外部客户端的 JSON API、SSE 或 LLM 的流式响应、RSS/XML 等非 UI 内容。

Route Handlers 就是 App Router 里的 API 端点：在 app/ 目录任意层级放一个 route.ts，导出按 HTTP 方法命名的异步函数即可。它基于标准 Web API——Request、Response，外加 Next 扩展的 NextRequest/NextResponse。

最小端点：GET 与 POST ​

ts
import { NextRequest } from 'next/server';

// GET /api/items —— 返回 JSON
export async function GET() {
  const items = await db.item.findMany();
  return Response.json(items); // 标准 Response.json，Content-Type 自动为 application/json
}

// POST /api/items —— 读取 JSON 请求体
export async function POST(request: NextRequest) {
  const body = await request.json(); // 请求体只在需要时读取
  if (typeof body.name !== 'string') {
    return Response.json({ error: 'name 必填' }, { status: 400 });
  }
  const item = await db.item.create({ data: { name: body.name } });
  return Response.json(item, { status: 201 });
}

支持的方法导出：GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。未导出的方法被调用时，框架自动返回 405 Method Not Allowed。

::: warn 默认不缓存 Route Handlers 默认在请求时执行、不缓存。经典模型下只有 GET 可以通过 export const dynamic = 'force-static' 显式选择静态；其它方法即使和静态 GET 写在同一文件里也绝不缓存。Cache Components 开启后，GET 与页面遵循同一套「无动态输入则预渲染」模型（进阶篇细讲）。 :::

动态段：await ctx.params ​

Route Handler 可以和页面共用动态段目录，参数通过第二个参数 context 传入，类型用全局的 RouteContext<'/路由'> 辅助类型。16 中 params 同样是 Promise：

ts
import type { NextRequest } from 'next/server';

export async function GET(
  _request: NextRequest,
  ctx: RouteContext<'/users/[id]'>
) {
  const { id } = await ctx.params; // 16：动态参数必须 await
  const user = await db.user.findById(id);
  if (!user) {
    return Response.json({ error: '用户不存在' }, { status: 404 });
  }
  return Response.json({ id: user.id, name: user.name });
}

流式响应 ​

返回 ReadableStream 即可获得流式输出——这是接入 LLM、日志推送等场景的基础形态，全程只使用 Web 标准：

ts
const encoder = new TextEncoder();

async function* makeChunks() {
  yield encoder.encode('data: 第一片内容\n\n');
  await new Promise((r) => setTimeout(r, 300));
  yield encoder.encode('data: 第二片内容\n\n');
  yield encoder.encode('data: [DONE]\n\n');
}

function iteratorToStream(asyncIterator: AsyncGenerator<Uint8Array>) {
  return new ReadableStream({
    async pull(controller) {
      const { value, done } = await asyncIterator.next();
      if (done) controller.close();
      else controller.enqueue(value);
    },
  });
}

export async function GET() {
  return new Response(iteratorToStream(makeChunks()), {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
    },
  });
}

与 page.tsx 的共存规则 ​

Route 是最低层级的路由原语：它不参与布局，也不参与客户端导航。文件树层面有一条硬规则——同一层级不能同时存在 route.ts 和 page.tsx：

文件组合结果
app/page.tsx + app/route.ts冲突，构建报错
app/page.tsx + app/api/route.ts合法（不同层级）
app/[user]/page.tsx + app/api/route.ts合法（不同层级）

命名建议

面向页面的数据接口统一放在 src/app/api/ 下；需要 Webhook 的放 src/app/api/webhook/...。这样 /api/* 可以在 proxy 与 CDN 层被整体识别和施加策略（第 9.2 篇会用到）。

Route Handler 还是 Server Action ​

两者都跑在服务端，按调用方与职责选择：

维度Route HandlerServer Action
调用方任意 HTTP 客户端、第三方系统你的 React UI（表单/transition）
方法任意 HTTP 方法仅 POST
响应完全自定义（JSON、流、XML、状态码）Flight 流（返回值 + 重渲染）
缓存失效可调 revalidateTag 等updateTag 等全部手段
适用Webhook、开放 API、流式表单变更、与 UI 联动的写操作

常见误区 ​

  • 误区一：忘记函数名大写。 必须导出 GET/POST，写成 get 不会被识别。
  • 误区二：在同层放 page.tsx 和 route.ts。 直接冲突，把子路径挪进 api/ 等子目录。
  • 误区三：16 里直接解构 ctx.params。 params 是 Promise，必须 await。
  • 误区四：把给 UI 的变更写成 Route Handler。 与 UI 联动的写操作优先用 Server Action，自动获得单往返重渲染。

小结 ​

  • Route Handler 是 app/ 树中的 route.ts，导出标准 HTTP 方法函数，签名是 (request, context)
  • 默认动态不缓存；动态参数 await ctx.params；返回 JSON、流或任意非 UI 内容都用标准 Response
  • 它与 page 不能同级共存，职责上与 Server Action 按「开放端点 vs UI 变更」分工
