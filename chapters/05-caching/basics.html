先立心智：不缓存才是默认值 ​

16.x 之前，开发者要花大量精力记住“哪些东西偷偷被缓存了”。16.x 翻转了模型：

  • 动态默认：数据读取默认在请求时执行，没有隐藏缓存
  • 缓存是显式动作：在函数或组件顶部写下 'use cache'，意图即代码
  • 缓存不是只有一个开关，而是由**寿命（cacheLife）+ 标签（cacheTag）+ 失效（revalidate/update）**三件套组成

这套能力统称 Cache Components，需要在配置中显式开启：

ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  cacheComponents: true, // 启用后 'use cache' / cacheLife / cacheTag 才生效
};

export default nextConfig;

开启后构建期会校验每段路由：任何无法在预渲染时完成的访问（未缓存取数、cookies()、随机值），都必须显式地被 <Suspense> 包裹或缓存——开发浮层会直接给出可操作的修复提示。

第一类用法：缓存数据函数 ​

'use cache' 写在异步函数体顶部，缓存的是函数返回值。数据库查询、ORM 调用、计算密集的聚合都适用：

ts
import { cacheLife } from 'next/cache';
import { db } from '@/lib/db';

export async function getProductList() {
  'use cache';
  cacheLife('hours'); // 商品目录一天多次变化，选 hours 档
  return db.product.findMany({
    select: { id: true, name: true, price: true },
  });
}

第二类用法：缓存整个组件 ​

把指令写在异步组件体顶部，缓存的是整段渲染输出（RSC 负载）。适合“与请求无关、变化不频繁”的 UI 块：

tsx
import { cacheLife, cacheTag } from 'next/cache';

export default async function EditorialPicks() {
  'use cache';
  cacheLife('days');        // 编辑精选每天更新
  cacheTag('picks');        // 打标签，运营改稿后可按需失效
  const picks = await getPicksFromCms();

  return (
    <section>
      <h2>编辑精选</h2>
      <ul>{picks.map((p) => <li key={p.id}>{p.title}</li>)}</ul>
    </section>
  );
}

TIP

官方建议每一个 'use cache' 作用域都显式配一个 cacheLife。不写时套用隐式 default 档（stale 5 分钟 / revalidate 15 分钟 / 永不过期），读代码的人无法直观看出寿命，嵌套缓存时行为还会相互影响。

cacheLife：七档预设 ​

cacheLife 接收预设档位名，三档时间的含义先建立直觉：

  • stale：浏览器客户端缓存可以不问服务器直接用多久
  • revalidate：服务端多久后在后台刷新一次
  • expire：多久完全过期，过期后下一个请求要等新内容
档位典型内容stalerevalidateexpire
seconds股价、实时比分30s1s1m
minutes社交信息流、新闻5m1m1h
hours库存、天气5m1h1d
days博客、文章5m1d1w
weeks播客、周报5m1w30d
max法律页、归档内容5m30d1y
default未显式指定时5m15m永不

选型依据是“内容多久变一次”，不是“这个页面重不重要”。实时数据用 seconds，CMS 文案配 webhook 失效时甚至可以直接用 max。

cacheTag：给缓存条目挂标签 ​

光有寿命不够：编辑刚改完文章，不能等明天才生效。cacheTag(...tags) 给条目挂逻辑标签，之后由失效函数按标签精准清除：

ts
import { cacheLife, cacheTag } from 'next/cache';

export async function getPost(slug: string) {
  'use cache';
  cacheLife('days');
  // 同时挂集合标签与单条标签：列表页与详情页可分别失效
  cacheTag('posts', `post-${slug}`);
  return db.post.findUnique({ where: { slug } });
}

标签规则：单次调用最多 128 个、每个最长 256 字符；重复挂同一标签幂等；标签区分大小写。

::: warn cacheLife 与 cacheTag 只能在 'use cache' 作用域内调用，且不能在模块顶层执行。写在函数体首行之后、业务逻辑之前即可；它们也不要抽进共享工具函数，缓存策略应当在调用处一眼可见。 :::

缓存键：参数天然参与 ​

你不需要手动拼缓存键。函数参数与闭包捕获的值自动成为缓存键的一部分，不同输入天然是不同条目：

ts
import { cacheLife } from 'next/cache';

export async function getPrice(sku: string, currency: string) {
  'use cache';
  cacheLife('minutes');
  // (sku='kb87', currency='CNY') 与 (sku='kb87', currency='USD') 各存一条
  const quote = await quoteService.fetch(sku, currency);
  return quote;
}

常见误区 ​

  • 没开 cacheComponents 就写 'use cache'：指令不生效，行为仍是动态默认。
  • 把随机值、Date.now() 直接放进缓存组件却不处理：开启校验后构建期就会报 blocking 洞察；要么缓存它（所有人共享一个值），要么 connection() + Suspense 延迟到请求时。
  • 在缓存组件里直接 cookies()：运行时数据不能进缓存组件，需要先在外层读取再以参数下发（进阶篇细讲）。
  • 用 seconds 档还指望它进静态外壳：寿命过短（revalidate 为 0 或 expire 低于 5 分钟）的缓存会成为请求时解析的“动态洞”。
  • 以为缓存键要手动拼：参数自动入键；手动 JSON.stringify 参数反而降低可读性。

小结 ​

  • 16.x 动态默认，缓存全部显式 opt-in，先在配置中开启 cacheComponents
  • 'use cache' 可标数据函数（缓存返回值）或组件（缓存渲染输出）
  • 每个缓存作用域显式声明 cacheLife 档位，并按内容变化频率选型
  • cacheTag 为按需失效铺路，函数参数自动构成缓存键
  • 运行时数据与随机值有明确的安置规则，不能混进缓存组件
