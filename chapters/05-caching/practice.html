场景：公告板的读缓存与写失效 ​

团队公告板有两条数据通路：

  • 读：公告列表与服务端时间戳。时间戳用来验证“我看到的页面是什么时候生成的”，列表希望绝大多数请求命中缓存
  • 写：管理员发布公告（Server Action），发布者本人必须立刻看到新内容，不能等寿命到期

需求落在三个技术决策上：读路径用 'use cache' + cacheLife('minutes') 并打标签；写路径完成数据库变更后调用 updateTag；时间戳用独立的短缓存便于观察命中。

落地步骤 ​

::: steps

  1. 确认 cacheComponents: true，数据读写全部收敛到 src/lib/ 与 src/app/actions/
  2. 为读函数加 'use cache'、显式 cacheLife 与集合/条目双层标签
  3. 页面以服务端组件取数，旁挂一个“页面生成时间戳”卡片做命中观测
  4. 写操作在 Server Action 中完成入库后调用 updateTag，再 redirect
  5. 为 Route Handler/Webhook 场景保留 revalidateTag 通道
  6. 压测与手测命中：寿命内刷新时间戳不变；发布后列表与时间戳立即更新
  7. 准备配置回滚开关，事故时能一键退回全动态 :::

第一步：带标签的读层 ​

ts
import { cacheLife, cacheTag } from 'next/cache';
import { db } from '@/lib/db';

// 时间戳卡片：缓存生成时刻，1 分钟寿命，肉眼可辨命中与否
export async function getPageTimestamp() {
  'use cache';
  cacheLife('minutes');
  return new Date().toISOString();
}

// 公告列表：集合标签负责整页失效
export async function listAnnouncements() {
  'use cache';
  cacheLife('minutes');
  cacheTag('announcements');
  return db.announcement.findMany({
    orderBy: { createdAt: 'desc' },
    select: { id: true, title: true, body: true },
  });
}

// 单条详情：集合 + 条目双标签
export async function getAnnouncement(id: string) {
  'use cache';
  cacheLife('days');
  cacheTag('announcements', `announcement-${id}`);
  return db.announcement.findUnique({ where: { id } });
}

TIP

时间戳是最朴素的缓存探针：缓存命中时它保持不变，失效或过期后才跳动。上线初期在角落保留这种探针（仅内测环境），排查“数据为什么不更新”能省掉大量猜测。

第二步：写后立即失效 ​

ts
'use server';

import { revalidatePath, updateTag } from 'next/cache';
import { redirect } from 'next/navigation';
import { db } from '@/lib/db';
import { requireAdmin } from '@/lib/auth';

export async function publishAnnouncement(formData: FormData) {
  // 服务端必须重复鉴权：Action id 可被构造，不能只依赖 UI 隐藏入口
  await requireAdmin();

  const title = String(formData.get('title') ?? '').trim();
  const body = String(formData.get('body') ?? '').trim();
  if (!title || !body) {
    return { error: '标题与内容不能为空' };
  }

  const created = await db.announcement.create({ data: { title, body } });

  // 立即过期：列表标签 + 新详情标签；下一次读取同步拿到新数据
  updateTag('announcements');
  updateTag(`announcement-${created.id}`);
  // 若页面对 URL 聚合还有疑虑，可补一次路径级兜底
  revalidatePath('/announcements');

  redirect(`/announcements/${created.id}`);
}

页面侧保持纯服务端读取，发布表单用第 7 章的 <form action={publishAnnouncement}> 渐进增强接入即可。此时时间戳也会随写操作更新——因为 Action 的失效调用会清空当前客户端缓存，绕开 stale 窗口。

第三步：给 Webhook 留第二条通道 ​

运营在外部 CMS 改稿不会经过我们的 Action，暴露一个受签名保护的 Route Handler，用 revalidateTag 做后台刷新即可（允许几秒延迟）：

ts
import { revalidateTag } from 'next/cache';

export async function POST(request: Request) {
  // 1) 校验原始签名头；2) 校验 tag 在白名单内
  if (request.headers.get('x-webhook-secret') !== process.env.WEBHOOK_SECRET) {
    return Response.json({ error: 'unauthorized' }, { status: 401 });
  }

  const payload = (await request.json()) as { tag?: string };
  const allowed = ['announcements', 'picks'];
  if (!payload.tag || !allowed.includes(payload.tag)) {
    return Response.json({ error: 'invalid tag' }, { status: 400 });
  }

  revalidateTag(payload.tag, 'max'); // 先服务旧内容，后台生成新内容
  return Response.json({ revalidated: true });
}

缓存事故回滚清单 ​

缓存出问题时最怕“线上数据错了但关不掉”。提前准备好分级手段：

现象立即动作根治动作
大面积旧数据配置开关关闭 cacheComponents，路由退回全动态排查标签是否漏挂/写错（大小写）
某类内容陈旧临时把该函数 cacheLife 调到 seconds 或去掉 'use cache'补齐写操作的 updateTag 链路
缓存了用户私有数据串号移除共享缓存，改用 'use cache: private' 或参数化 sessionId审计缓存键是否包含会话维度
Webhook 失效不生效手工调用一次 revalidatePath 兜底校验签名、tag 白名单与部署 ID
Serverless 命中率极低不依赖内存缓存的正确性；接 cacheHandlers 远端存储评估 'use cache: remote' 的网络成本
发布后仍不更新确认新部署会清空缓存（缓存键含 build id）检查是否误依赖跨部署持久化

DANGER

私有数据事故优先级最高。任何包含用户身份结果的缓存，要么以 sessionId 为参数参与缓存键，要么使用只存浏览器的 'use cache: private'。共享缓存里放个性化内容会造成用户间数据串号，这是必须进代码评审检查项的红线。

在线演练：命中、陈旧与失效 ​

演练场在浏览器内存里模拟公告读缓存：反复“读取”看到同一个时间戳（命中）；发布公告对应 updateTag，立即过期，下一次读取拿到新时间戳。这正是本节两条失效路径的语义差：

最佳实践清单 ​

  • [ ] 每个 'use cache' 都有显式 cacheLife，调用处一眼可见寿命
  • [ ] 标签成对设计：集合标签（一类）+ 条目标签（单资源）
  • [ ] Server Action 写后失效统一用 updateTag，随后再 redirect
  • [ ] Route Handler/Webhook 失效用 revalidateTag(tag, 'max')，签名与 tag 白名单双校验
  • [ ] 私有数据参数化会话键或使用 private 变体，永不进共享缓存
  • [ ] 高成本缓存函数评估远端缓存处理器，默认内存在 Serverless 不保证命中
  • [ ] 保留环境化的缓存探针（时间戳/命中日志），便于线上排查
  • [ ] 为关闭缓存准备配置开关与回滚文档，并演练一次
