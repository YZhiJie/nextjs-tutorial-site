场景：搜索页的交互与数据 ​

商品搜索页有这些需求：

  • 首屏服务端渲染商品列表，标题、价格、标签直接进 HTML，对 SEO 友好
  • 顶部搜索框与分类筛选即时响应，输入即过滤已加载的数据
  • “收藏”按钮需要登录态与乐观反馈
  • 商品卡要在首页、活动页、搜索页复用

新手最常见的写法是整个 page.tsx 顶部一行 'use client'，然后在 useEffect 里 fetch 商品。结果：首屏只有 loading 空壳、密钥与接口结构被迫暴露成公开 API、整页 JS 翻倍。下面按正确方式落地。

落地步骤 ​

::: steps

  1. 圈出交互：搜索框、筛选 chips、收藏按钮——只有这些是客户端叶子
  2. 服务端页面负责取数，把可序列化的商品数组作为 props 下发
  3. 商品卡保持服务端组件；收藏按钮作为客户端叶子嵌在卡内
  4. 过滤组件只接收数据与受控状态，不感知数据来源
  5. 用构建产物与浏览器 Network 面板验证：首屏 HTML 含列表，JS 只覆盖交互区 :::

第一步：确定组件树 ​

text
SearchPage（server）
├─ <SearchAndFilter>（client：输入、分类 state）
│  └─ 纯 props 驱动，无任何 fetch
├─ 商品网格（server：map 渲染）
│  └─ <ProductCard>（server）
│     ├─ 标题/价格/标签（server，零 JS）
│     └─ <FavoriteButton>（client：登录态 + 乐观 UI）
└─ <Pagination>（server：<Link> 生成页码）

第二步：服务端数据壳 ​

tsx
import SearchAndFilter from '@/app/ui/search/search-and-filter';
import ProductCard from '@/app/ui/product/product-card';
import { searchProducts } from '@/lib/products';

export default async function SearchPage(
  props: PageProps<'/search'>
) {
  const { category, q } = await props.searchParams;
  // 数据库查询、权限过滤、字段裁剪全部在服务端完成
  const products = await searchProducts({
    category: typeof category === 'string' ? category : undefined,
    q: typeof q === 'string' ? q : undefined,
  });

  // 只下发可序列化的 DTO：id、名称、价格、标签，绝不下传数据库行对象
  return (
    <main className="mx-auto max-w-5xl p-6">
      <h1>商品搜索</h1>
      <SearchAndFilter
        initialQuery={q ?? ''}
        products={products.map((p) => ({
          id: p.id,
          name: p.name,
          price: p.price,
          tags: p.tags,
        }))}
      />
    </main>
  );
}

第三步：客户端过滤叶子与服务端卡片 ​

tsx
'use client';

import { useMemo, useState } from 'react';
import ProductCard from '@/app/ui/product/product-card';

type ProductDTO = {
  id: string;
  name: string;
  price: number;
  tags: string[];
};

export default function SearchAndFilter({
  initialQuery,
  products,
}: {
  initialQuery: string;
  products: ProductDTO[];
}) {
  const [query, setQuery] = useState(initialQuery);

  // 过滤纯客户端完成，不重新请求服务端（数据已随首屏下发）
  const visible = useMemo(() => {
    const kw = query.trim().toLowerCase();
    if (!kw) return products;
    return products.filter(
      (p) =>
        p.name.toLowerCase().includes(kw) ||
        p.tags.some((t) => t.toLowerCase().includes(kw))
    );
  }, [query, products]);

  return (
    <section>
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="过滤已加载的商品…"
        className="w-full rounded-lg border px-4 py-2"
        aria-label="过滤商品"
      />
      <p className="mt-2 text-sm text-gray-500">
        共 {visible.length} / {products.length} 件
      </p>
      <div className="mt-4 grid grid-cols-3 gap-4">
        {visible.map((p) => (
          <ProductCard key={p.id} product={p} />
        ))}
      </div>
    </section>
  );
}

TIP

SearchAndFilter 是客户端组件，但它渲染的 ProductCard 是从服务端组件作为模块 import 的吗？——不是。一旦在客户端文件里 import，ProductCard 就进入客户端图。若卡片必须保持服务端零 JS，做法是在服务端页面预先渲染好卡片数组，作为渲染好的元素（或按 id 映射的元素）传入，第 3.2 篇的 children 模式即此思路；若卡片本身很轻，让它随叶子一起客户端化也是合理取舍。架构决策取决于卡片重量与交互密度。

“这段代码放哪”决策表 ​

拿不准时从上往下逐条问，命中即决策：

判断问题是 → 归属
用到密钥、数据库、内部服务吗？服务端
输出主要为静态文本/列表，且追求首屏与 SEO 吗？服务端
需要事件处理器、useState/useEffect、浏览器 API 吗？客户端
是第三方库且内部依赖浏览器能力吗？客户端（wrapper 包裹）
是服务端取数后驱动的交互 UI 吗？服务端取数 + 客户端叶子接收 props
需要在交互容器中展示服务端内容吗？children 透传
全局共享的状态/主题/语言吗？客户端 Provider，就近包裹

最佳实践清单 ​

  • [ ] 每个客户端组件都能一句话回答“它独占了什么交互”，答不上来就拆掉边界
  • [ ] 跨边界传 DTO（普通对象），不传数据库行、类实例、函数
  • [ ] 客户端组件不发取数请求，除非数据确实依赖客户端交互（第 4 章展开）
  • [ ] 服务端密钥文件顶部加 import 'server-only'，构建期拦截误引入
  • [ ] 通用展示组件不写 'use client'，边界放在交互叶子入口
  • [ ] 第三方交互库一律经 src/app/ui/wrappers/ 薄包装引入
  • [ ] Provider 就近嵌套，不包 <html>
  • [ ] 复用组件变更时检查：新增交互后是否该抽出新的 client 叶子，而不是给原文件加指令

本章检查清单 ​

  • [ ] 能默写服务端/客户端组件在 HTML 产出与 JS 下发上的差异
  • [ ] 能对任意一段代码用决策表判断归属并说明理由
  • [ ] 能实现 server 壳 + client 叶子 + 服务端卡片透传的组合
  • [ ] 能为第三方客户端库编写薄包装并保留服务端取数
  • [ ] 能说出一条 import 边如何影响客户端包体积
  • [ ] 能定位“函数不能作为 props”“Element type is invalid”两类报错的根因
