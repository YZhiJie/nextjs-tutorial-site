默认就是服务端组件 ​

在 App Router 里，page.tsx、layout.tsx 以及你自己新建的组件，默认全部是服务端组件——组件代码只在服务器运行，不会打包进浏览器 JS。下面这个组件除了 React 运行时的基础开销外，不向浏览器发送任何它自身的代码：

tsx
import { db } from '@/lib/db';

export default async function ProductsPage() {
  // 密钥、数据库查询、文件系统读取都可以直接写在这里
  const products = await db.product.findMany();

  return (
    <ul>
      {products.map((p) => (
        <li key={p.id}>{p.name}</li>
      ))}
    </ul>
  );
}

服务端组件擅长的事：直接查数据库、调用内部服务、使用密钥、渲染大段静态内容。代价是它不能使用 useState、useEffect、事件处理器和浏览器 API。

什么时候才需要 'use client' ​

在文件顶部写一行 'use client'，就在模块图上画出了一条边界：这个文件以及它 import 的所有模块进入客户端包。判断标准非常朴素——这段逻辑是否必须在浏览器里响应变化：

需求归属典型 API
读取数据库 / 调用内部接口服务端await db...
使用密钥、服务端令牌服务端process.env.API_KEY
点击、输入、拖拽等事件客户端onClick、onChange
组件状态与生命周期客户端useState、useEffect
浏览器能力客户端localStorage、window、地理定位
自定义 hook（含上述能力）客户端useXxx()
tsx
'use client';

import { useState } from 'react';

export default function AddToCartButton({ sku }: { sku: string }) {
  const [added, setAdded] = useState(false);

  return (
    <button
      className="primary"
      disabled={added}
      onClick={() => setAdded(true)}
    >
      {added ? '已加入购物车' : `加入购物车 · ${sku}`}
    </button>
  );
}

TIP

'use client' 只需要写在客户端子树的入口文件顶部。这个文件 import 的其他组件自动属于客户端包，不需要每个文件都重复声明；反过来，它也不会“感染”通过 children 传入的服务端组件（进阶篇细讲）。

关键澄清：客户端组件也会被服务端渲染成 HTML ​

“Client Component”这个名字最常见的误解是：它只在浏览器渲染。事实是它会经历两次渲染：

组件类型服务端产出 HTML浏览器是否收到组件代码
服务端组件是否（零客户端 JS）
客户端组件是（首屏）是，水合后附加交互

所以首屏到达浏览器时，按钮的文字、商品的价格都已经在 HTML 里，爬虫与弱网用户先看到完整内容；JS 下载完成后 React 再把事件处理器“水合”到已有 DOM 上。客户端导航（点 <Link> 跳转）时才是只下发 RSC 负载、在浏览器内渲染客户端组件。

在客户端组件里加一行日志可以直观验证：直接访问页面时，终端与浏览器控制台各打印一次。

tsx
'use client';

export default function Hello() {
  // 直接访问：服务端打印一次，浏览器水合时再打印一次
  console.log('Hello rendered');
  return <p>Hello</p>;
}

推荐结构：server 壳 + client 叶子 ​

最健康的组件树长这样：页面在服务端取数、组装布局，只把真正需要交互的小叶子标记为客户端：

tsx
import { notFound } from 'next/navigation';
import AddToCartButton from '@/app/ui/add-to-cart-button';
import { getProduct } from '@/lib/products';

export default async function ProductPage(
  props: PageProps<'/products/[sku]'>
) {
  const { sku } = await props.params;
  const product = await getProduct(sku);
  if (!product) notFound();

  return (
    <article className="p-8">
      <h1>{product.name}</h1>
      <p className="text-xl">{product.price}</p>
      {/* 唯一的交互叶子：只把它的 JS 发给浏览器 */}
      <AddToCartButton sku={product.sku} />
    </article>
  );
}

常见误区 ​

  • 在页面顶部无脑加 'use client'：整页立刻进入客户端包，数据库驱动、密钥能力全部失效，JS 体积随页面线性膨胀。
  • 把“有交互”等同于“整棵树都要客户端”：需要的是最小交互叶子，不是容器。
  • 在服务端组件里写 onClick：构建期直接报错；事件处理器无法跨序列化边界。
  • 认为客户端组件不产出 HTML：首屏 HTML 与水合是两件事，动态内容的初始形态照样在 HTML 里。
  • 客户端组件里直连数据库：它的代码会下发浏览器，查询语句与凭据全部泄漏；取数留在服务端，再以 props 传入。

小结 ​

  • App Router 组件默认只跑在服务器，不向浏览器发送自身代码
  • 'use client' 是模块边界，只为状态、事件、浏览器 API 而画
  • 客户端组件同样经历服务端首屏渲染，水合只负责附加交互
  • 最优结构是“服务端壳取数与布局 + 最小客户端叶子负责交互”
