渲染流水线：Layout → Paint → Composite ​

度量篇（12.1）把 INP 定义为"交互到下一次绘制"，但没说"绘制"到底经历什么。浏览器把一次视觉更新拆成三个阶段，改动的属性决定走到哪一步，成本指数级递增：

阶段做什么触发属性（举例）成本
Layout（布局）计算每个元素的几何位置与尺寸width、height、top、margin、padding、font-size最高，影响子树
Paint（绘制）把元素像素画到图层color、background、box-shadow、border-color中，受图层面积影响
Composite（合成）把多个图层按顺序叠加到屏幕transform、opacity、filter（部分）最低，GPU 完成

优化的第一性原理：让动画和高频更新只触发 Composite。transform: translateX() 与 left 视觉效果相同，但前者只合成、后者每帧重排整棵子树——在中端手机上就是 60fps 与 20fps 的区别。

INFO

现代浏览器对 opacity 与 transform 做了特殊优化：只要元素拥有独立合成层（compositing layer），这两个属性的变化完全在 GPU 合成阶段完成，不回流不重绘。这就是"GPU 加速"的本质——不是浏览器突然变快，而是把活从 CPU 主线程挪到了 GPU 合成线程。

GPU 加速：把动画放到合成层 ​

① 动画只用 transform 与 opacity ​

diff
- .menu { left: -240px; transition: left 0.3s; }
- .menu.open { left: 0; }          /* 每帧触发布局重排 */
+ .menu { transform: translateX(-240px); transition: transform 0.3s; }
+ .menu.open { transform: translateX(0); }  /* 仅合成，GPU 完成 */

② will-change：提前声明，不要滥用 ​

will-change 告诉浏览器"这个属性即将变化"，浏览器会预先为它创建合成层。但每个合成层都占显存，动辄几百个元素全开 will-change: transform 会导致移动端内存爆掉。

css
.menu { transition: transform 0.3s; }
.menu.animating { will-change: transform; } /* 动画开始前由 JS 加 class */
1
2

DANGER

不要写 * { will-change: transform; }。这等于让浏览器给每个元素都建层，显存与合成开销反而比不加速更差。will-change 是给"已知即将动画的少数元素"用的。

③ transform: translateZ(0) 是旧时代的遗产 ​

translateZ(0)（或 translate3d(0,0,0)）的作用是强制浏览器为元素创建合成层，在 2015 年前后是"开启 GPU 加速"的标准 hack。今天它仍然有效，但更推荐：

  • 用 will-change 显式声明意图
  • 或者依赖浏览器对 transform/opacity 动画的自动层提升

只有在"需要在非动画状态下也保持独立层（例如避免首次动画时的图层创建卡顿）"时，才用 translateZ(0) 做层提升。

④ contain：渲染隔离 ​

contain 属性声明"这个元素的内部变化不影响外部"，浏览器据此跳过对外部的布局/绘制计算。长列表的每一项、独立弹窗、侧边栏都适合加：

css
.list-item { contain: layout paint; }    /* 内部布局/绘制不向外传播 */
.modal      { contain: layout paint size; } /* size 意味着尺寸不依赖内容 */
1
2

contain: strict（= layout paint size style）隔离最彻底，但要求你自己管理尺寸；contain: content（不含 size）更宽松，是大多数场景的安全起点。

帧预算：16ms 与长任务 ​

60fps 要求每帧 ≤ 16.67ms。这 16ms 里浏览器要做：执行 JS → Style → Layout → Paint → Composite。JS 占用越多，留给渲染的时间越少。

长任务是 INP 的元凶 ​

任何单次执行超过 50ms 的 JS 任务都算长任务（Long Task）。它会阻塞主线程，用户的点击/输入得不到响应，INP 直接劣化。常见来源：

  • 大数组同步遍历/排序
  • 复杂的 JSON 序列化/反序列化
  • 大列表一次性渲染上千个 DOM 节点
  • 重型库的初始化（富文本、图表、Markdown 引擎）

拆分长任务：让出主线程 ​

把一个 200ms 的任务拆成 4 个 50ms 的片段，中间用 scheduler.yield()（或 setTimeout 兜底）交还主线程，让浏览器有机会处理用户输入和渲染：

ts
export function yieldToMain(): Promise<void> {
  // 优先用原生 scheduler.yield（Chrome 115+），回退到 setTimeout
  if ('scheduler' in globalThis && 'yield' in (globalThis as any).scheduler) {
    return (globalThis as any).scheduler.yield();
  }
  return new Promise((r) => setTimeout(r, 0));
}

export async function processInChunks<T>(
  items: T[],
  chunkSize: number,
  fn: (item: T) => void,
): Promise<void> {
  for (let i = 0; i < items.length; i += chunkSize) {
    items.slice(i, i + chunkSize).forEach(fn);
    await yieldToMain(); // 每处理完一块就让出主线程
  }
}

requestAnimationFrame：与浏览器绘制对齐 ​

动画和逐帧更新必须用 requestAnimationFrame（rAF），它保证回调在浏览器下一次绘制前执行，与刷新率对齐，避免掉帧和视觉撕裂：

ts
function smoothScrollTo(targetY: number) {
  const startY = window.scrollY;
  const diff = targetY - startY;
  const duration = 300;
  let start: number | null = null;

  function step(ts: number) {
    if (start === null) start = ts;
    const progress = Math.min((ts - start) / duration, 1);
    // easeOutCubic
    const eased = 1 - Math.pow(1 - progress, 3);
    window.scrollTo(0, startY + diff * eased);
    if (progress < 1) requestAnimationFrame(step);
  }
  requestAnimationFrame(step);
}

布局抖动：强制同步布局 ​

在一帧内先读布局属性再写布局属性，浏览器被迫立即同步计算布局，打断正常的异步批处理。循环里反复读写就是布局抖动（layout thrashing）：

ts
// 每次循环都强制同步布局 → N 次重排
for (const el of list) {
  const h = el.offsetHeight;       // 读：强制布局
  el.style.height = `${h * 2}px`;  // 写：使布局失效，下一次读又重排
}

滚动监听必须 passive ​

touchstart、touchmove、wheel、mousewheel 这类滚动事件，默认浏览器要等监听器执行完才决定是否滚动（因为你可能 preventDefault），导致滚动卡顿。加 passive: true 告诉浏览器"我不会阻止默认行为"，滚动立即响应：

ts
window.addEventListener('scroll', onScroll, { passive: true });
window.addEventListener('touchmove', onTouchMove, { passive: true });

长列表虚拟化 ​

一次性渲染 1000 个 <li> 会创建 1000 个 DOM 节点，首屏渲染与内存都吃不消。虚拟化（virtualization）只渲染视口内可见的那几条，滚动时动态替换：

tsx
'use client';

import { FixedSizeList as List } from 'react-window';

const DATA = Array.from({ length: 10000 }, (_, i) => `第 ${i + 1} 条数据`);

function Row({ index, style }: { index: number; style: React.CSSProperties }) {
  return <div style={style}>{DATA[index]}</div>;
}

export function VirtualList() {
  return (
    <List
      height={400}          // 容器高度
      itemCount={DATA.length}
      itemSize={36}         // 每行高度（固定高度最简单）
      width="100%"
    >
      {Row}
    </List>
  );
}

React 并发：让交互永远跟手 ​

React 19 的并发渲染把"渲染"变成可中断、可优先级调度的工作。两个直接面向开发者的 API：

useTransition：把更新标记为"不紧急" ​

startTransition 包裹的状态更新会被标记为低优先级，React 可以在渲染中途让位于更高优先级的更新（如用户输入）：

tsx
'use client';

import { useState, useTransition } from 'react';

export function SearchBox({ allItems }: { allItems: string[] }) {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState<string[]>([]);
  const [isPending, startTransition] = useTransition();

  const onChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value;
    setQuery(value); // 紧急：输入框必须立刻显示
    startTransition(() => {
      // 非紧急：过滤大数组可以慢一点，不阻塞输入
      setResults(allItems.filter((i) => i.includes(value)));
    });
  };

  return (
    <div>
      <input value={query} onChange={onChange} />
      {isPending && <span className="muted">筛选中…</span>}
      <ul>{results.map((r) => <li key={r}>{r}</li>)}</ul>
    </div>
  );
}

useDeferredValue：延迟一个值的更新 ​

当你无法控制状态更新的源头（例如 props 从父组件传来），用 useDeferredValue 拿到一个"延迟版本"，React 会在紧急更新之后再同步它：

tsx
'use client';

import { useDeferredValue, useMemo } from 'react';

export function SlowList({ items }: { items: string[] }) {
  const deferredItems = useDeferredValue(items);
  const visible = useMemo(
    () => deferredItems.slice(0, 200),
    [deferredItems],
  );
  const isStale = items !== deferredItems;
  return (
    <div style={{ opacity: isStale ? 0.7 : 1 }}>
      {visible.map((i) => <div key={i}>{i}</div>)}
    </div>
  );
}

IntersectionObserver：把轮询换成事件 ​

IntersectionObserver 让浏览器在元素进入/离开视口时通知你，比 scroll 事件里手动算 getBoundingClientRect() 高效得多——后者每次滚动都在主线程跑 JS。

典型用途：图片懒加载、无限滚动、滚动动画触发。

tsx
'use client';

import { useEffect, useRef, useState } from 'react';

export function LazyImage({ src, alt, ...rest }: { src: string; alt: string } & React.ImgHTMLAttributes<HTMLImageElement>) {
  const ref = useRef<HTMLImageElement>(null);
  const [visible, setVisible] = useState(false);

  useEffect(() => {
    const el = ref.current;
    if (!el) return;
    const io = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          setVisible(true);
          io.disconnect(); // 加载后不再观察
        }
      },
      { rootMargin: '200px' }, // 提前 200px 预加载
    );
    io.observe(el);
    return () => io.disconnect();
  }, []);

  return (
    <img
      ref={ref}
      src={visible ? src : undefined}
      alt={alt}
      loading="lazy"
      {...rest}
    />
  );
}

Web Worker：把重计算挪出主线程 ​

主线程负责渲染与交互，任何超过几毫秒的纯计算都应该丢给 Web Worker。Worker 与主线程通过 postMessage 通信，各自独立运行，互不阻塞。

ts
self.onmessage = (e: MessageEvent<number[]>) => {
  const sorted = [...e.data].sort((a, b) => a - b); // 万级排序在 Worker 里完成
  self.postMessage(sorted);
};

tsx
'use client';

import { useEffect, useRef, useState } from 'react';

export function SortDemo() {
  const workerRef = useRef<Worker | null>(null);
  const [result, setResult] = useState<number[]>([]);

  useEffect(() => {
    workerRef.current = new Worker(new URL('./heavy.worker.ts', import.meta.url));
    workerRef.current.onmessage = (e) => setResult(e.data);
    return () => workerRef.current?.terminate();
  }, []);

  const sortLargeArray = () => {
    const data = Array.from({ length: 50000 }, () => Math.random() * 100000);
    workerRef.current?.postMessage(data); // 不阻塞主线程，UI 始终响应
  };

  return (
    <div>
      <button onClick={sortLargeArray}>排序 5 万条（Worker）</button>
      <p>排序结果前 5 个：{result.slice(0, 5).join(', ')}</p>
    </div>
  );
}

白屏根因图谱 ​

"白屏"不是一个问题，而是一类现象的统称。按"白屏发生在什么阶段"分类，根因和解法完全不同：

白屏阶段典型根因排查方向解法
导航等待白屏点击链接后服务端慢查询阻塞第 6 章 Instant Navigation预取 + Stream/Block 策略 + 骨架屏
取数阻塞白屏页面顶层 await 最慢接口第 4 章流式渲染分块 Suspense + 骨架，LCP 元素放边界外
JS 下载白屏首屏 JS 体积过大，弱网下下载慢12.2 Bundle 分析分包、next/dynamic、删冗余依赖
JS 执行白屏客户端组件初始化同步执行重计算Performance 面板 Long TaskWeb Worker、useTransition、拆任务
Hydration 失败白屏服务端与客户端 HTML 不一致控制台 hydration mismatch 报错检查时间/随机数/useEffect 内改状态；用 suppressHydrationWarning 兜底
字体白屏（FOIT）外链字体未加载完，文字不可见Network 面板字体请求next/font 自托管 + font-display: swap
错误边界白屏error.tsx/global-error.tsx 未兜底控制台未捕获异常根布局必须有 global-error.tsx 且渲染 <html>/<body>

DANGER

第 2 章实战提过：global-error.tsx 必须自己渲染 <html> 和 <body>，且声明 'use client'。忘了 <html> 标签会导致整页白屏且没有任何报错边界兜底——这是最隐蔽的白屏之一。

TIP

排查白屏的标准动作：先看 Network 确认资源是否返回，再看 Console 确认是否有报错，最后用 Performance 面板录一段看时间线卡在哪。三者结合能定位 90% 的白屏。

实战案例集 ​

前面的原理都对，但落地时最容易踩坑的是"知道该用 transform，却在真实业务里写出了布局抖动"。下面 10 个案例覆盖企业后台最高频的卡顿场景，每个都给出反面写法与正确写法的完整对比。

测量口径说明 ​

下列指标为典型企业场景下的参考区间，实测值取决于设备档位、数据规模与浏览器版本，不构成承诺。统一测量条件：

  • 设备：中端安卓机（骁龙 7 系 / 8GB RAM）或同等性能桌面浏览器（Chrome，CPU 4x throttling）
  • 网络：Fast 3G（1.6 Mbps 下行 / 0.75 Mbps 上行，150ms RTT）节流
  • 指标采集：Chrome DevTools Performance 面板录制 + Lighthouse 10 次取中位数
  • 数据规模：标注在每个案例内（如 30 字段、5 万条等）
  • 对比口径：反面写法 vs 正面写法，同设备同数据同操作路径

::: warn 所有数字均为区间而非精确值——不同业务的 DOM 复杂度、CSS 选择器开销、第三方脚本干扰都会显著影响结果。你的项目必须在相同口径下复测，不能直接照搬。 :::

案例一：滚动吸顶（Sticky Header） ​

后台几乎每个列表页都有"滚动到某位置时表头吸顶"的需求。反面写法是 scroll 事件里读 scrollTop 再写 position——每次滚动都强制同步布局：

tsx
'use client';

import { useEffect, useRef, useState } from 'react';

export function StickyHeaderBad() {
  const [stuck, setStuck] = useState(false);
  const ref = useRef<HTMLDivElement>(null);

  useEffect(() => {
    const onScroll = () => {
      const el = ref.current;
      if (!el) return;
      const rect = el.getBoundingClientRect(); // 读：强制布局
      setStuck(rect.top <= 0);                  // 写：触发 React 重渲染
    };
    window.addEventListener('scroll', onScroll); // 还没加 passive
    return () => window.removeEventListener('scroll', onScroll);
  }, []);

  return (
    <div ref={ref} style={{ position: stuck ? 'fixed' : 'static', top: 0 }}>
      表头
    </div>
  );
}

案例二：FLIP 列表重排动画 ​

拖拽排序、筛选后列表项重新排列时，直接给 transition: all 会导致元素从旧位置"飘"到新位置，中间经过的每一帧都触发布局。FLIP 技术（First → Last → Invert → Play）只在最后一帧用 transform 做合成动画，过程中不触发任何布局：

tsx
'use client';

import { useLayoutEffect, useRef } from 'react';

/**
 * 列表重排时给每个项目加 FLIP 动画。
 * 调用时机：state 更新导致 DOM 位置变化后，在 useLayoutEffect 里执行。
 */
export function useFlipAnimation<T extends HTMLElement>(deps: unknown[]) {
  const prevPositions = useRef<Map<string, DOMRect>>(new Map());

  useLayoutEffect(() => {
    const items = document.querySelectorAll<HTMLElement>('[data-flip-id]');
    const first = prevPositions.current;

    items.forEach((el) => {
      const id = el.dataset.flipId!;
      const last = el.getBoundingClientRect();
      const prev = first.get(id);

      if (prev) {
        const dx = prev.left - last.left;
        const dy = prev.top - last.top;
        if (dx !== 0 || dy !== 0) {
          // Invert：先把元素挪回原位
          el.style.transform = `translate(${dx}px, ${dy}px)`;
          el.style.transition = 'none';
          // 强制浏览器应用 Invert 状态
          el.offsetWidth; // 读布局，触发重排（仅此一次）
          // Play：清除 transform，让 transition 动画到真实位置
          el.style.transform = '';
          el.style.transition = 'transform 0.3s ease';
        }
      }
      first.set(id, last);
    });
  }, deps);
}

'use client';

import { useEffect, useRef, useState } from 'react';
import { FixedSizeList as List } from 'react-window';

const PAGE_SIZE = 50;

export function InfiniteFeed() {
  const [items, setItems] = useState<number[]>([]);
  const [loading, setLoading] = useState(false);
  const sentinelRef = useRef<HTMLDivElement>(null);

      </div>
    </div>
  );

案例四：表单实时校验防抖 ​

注册表单、搜索建议这类"边输入边校验"的场景，校验逻辑可能很重（查远程接口、跑正则大文本）。如果每次 onChange 都同步校验，输入会卡顿。正确做法是输入即时更新 + 校验延迟执行 + useTransition 不阻塞输入：

tsx
'use client';

import { useState, useTransition, useRef, useEffect } from 'react';

// 模拟一个很重的校验：查远程接口 + 正则匹配
async function heavyValidate(value: string): Promise<string | null> {
  await new Promise((r) => setTimeout(r, 400));
  if (value.length < 6) return '至少 6 位';
  if (!/^[a-zA-Z0-9]+$/.test(value)) return '只能字母数字';
  return null;
}

export function ValidatedInput() {
  const [value, setValue] = useState('');
  const [error, setError] = useState<string | null>(null);
  const [isPending, startTransition] = useTransition();
  const timer = useRef<ReturnType<typeof setTimeout> | null>(null);

  const onChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const v = e.target.value;
    setValue(v); // 紧急：输入框立刻显示

    // 防抖 300ms，避免每次按键都触发校验
    if (timer.current) clearTimeout(timer.current);
    timer.current = setTimeout(() => {
      startTransition(async () => {
        // 非紧急：重校验不阻塞用户继续输入
        setError(await heavyValidate(v));
      });
    }, 300);
  };

  useEffect(() => () => {
    if (timer.current) clearTimeout(timer.current);
  }, []);

  return (
    <div>
      <input value={value} onChange={onChange} />
      {isPending && <span className="muted">校验中…</span>}
      {error && <span style={{ color: '#b91c1c' }}>{error}</span>}
    </div>
  );
}

tsx
'use client';

import { useEffect, useRef } from 'react';

export function ScrollProgress() {
  const barRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    let ticking = false;

    const update = () => {
      const bar = barRef.current;
      if (!bar) return;
      const scrollTop = window.scrollY;
      const max = document.documentElement.scrollHeight - window.innerHeight;
      const progress = max > 0 ? scrollTop / max : 0;
      // scaleX 只触发合成层，不布局不重绘
      bar.style.transform = `scaleX(${progress})`;
      ticking = false;
    };

    const onScroll = () => {
      if (!ticking) {
        // 用 rAF 把多次 scroll 合并为一次绘制
        requestAnimationFrame(update);
        ticking = true;
      }
    };

    window.addEventListener('scroll', onScroll, { passive: true });
    return () => window.removeEventListener('scroll', onScroll);
  }, []);

  return (
    <div
      style={{
        position: 'fixed',
        top: 0,
        left: 0,
        height: 3,
        width: '100%',
        background: '#047857',
        transformOrigin: 'left center',
        transform: 'scaleX(0)',
        zIndex: 9999,
      }}
      ref={barRef}
    />
  );
}

企业后台的表单动辄 30+ 字段（输入框、下拉、日期、开关）。反面写法是把所有字段的 state 放在顶层组件，每次任意一个字段输入，整棵表单树（含所有字段的渲染）都重跑：

tsx
'use client';

import { useState, useCallback } from 'react';

interface TreeNode {
  id: string;
  label: string;
  children?: TreeNode[];
  hasChildren?: boolean;
}

// 递归收集"展开路径上的可见行"，未展开的子树不进入结果
function collectVisible(
  nodes: TreeNode[],
  expanded: Set<string>,
  depth = 0,
): Array<{ node: TreeNode; depth: number }> {
  const result: Array<{ node: TreeNode; depth: number }> = [];
  for (const node of nodes) {
    result.push({ node, depth });
    if (node.children && expanded.has(node.id)) {
      result.push(...collectVisible(node.children, expanded, depth + 1));
    }
  }
  return result;
}

export function TreeTable({ rootNodes }: { rootNodes: TreeNode[] }) {
  const [expanded, setExpanded] = useState<Set<string>>(new Set());
  const [loaded, setLoaded] = useState<Map<string, TreeNode[]>>(new Map());

  const toggle = useCallback(async (node: TreeNode) => {
    setExpanded((prev) => {
      const next = new Set(prev);
      if (next.has(node.id)) next.delete(node.id);
      else next.add(node.id);
      return next;
    });
    // 首次展开时才拉取子节点（懒加载）
    if (node.hasChildren && !loaded.has(node.id)) {
      const children = await fetch(`/api/nodes/${node.id}/children`).then((r) => r.json());
      setLoaded((prev) => new Map(prev).set(node.id, children));
    }
  }, [loaded]);

  const visible = collectVisible(rootNodes, expanded);

  return (
    <table>
      <tbody>
        {visible.map(({ node, depth }) => (
          <tr key={node.id}>
            <td style={{ paddingLeft: depth * 24 }}>
              {node.hasChildren && (
                <button onClick={() => toggle(node)}>
                  {expanded.has(node.id) ? '▼' : '▶'}
                </button>
              )}
              {node.label}
            </td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}

'use client';

import { useEffect, useRef, useState } from 'react';

interface PinImage {
  id: string;
  url: string;
  title: string;
  width: number;
  height: number; // 服务端返回原始尺寸
}

function LazyPin({ img }: { img: PinImage }) {
  const ref = useRef<HTMLImageElement>(null);
  const [loaded, setLoaded] = useState(false);

  useEffect(() => {
    const el = ref.current;
    if (!el) return;
    const io = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          el.src = img.url; // 进入视口才设置 src
          io.disconnect();
        }
      },
      { rootMargin: '300px' },
    );
    io.observe(el);
    return () => io.disconnect();
  }, [img.url]);

  return (
    <figure>
      {/* aspect-ratio 用原始宽高比预占位，图片加载不改变布局 */}
      <div style={{ aspectRatio: `${img.width} / ${img.height}`, background: '#f4f4f5' }}>
        <img
          ref={ref}
          alt={img.title}
          style={{ width: '100%', height: '100%', objectFit: 'cover', opacity: loaded ? 1 : 0, transition: 'opacity 0.3s' }}
          onLoad={() => setLoaded(true)}
        />
      </div>
      <figcaption>{img.title}</figcaption>
    </figure>
  );
}

export function Masonry({ images }: { images: PinImage[] }) {
  return (
    <div style={{ columns: '3 200px', columnGap: 16 }}>
      {images.map((img) => (
        <div key={img.id} style={{ breakInside: 'avoid', marginBottom: 16 }}>
          <LazyPin img={img} />
        </div>
      ))}
    </div>
  );
}

案例九：大文本搜索高亮 ​

文档站、日志查看器需要在几万字的文本里高亮搜索关键词。反面写法是在渲染阶段用正则把全文切成"匹配/非匹配"片段数组——每次输入都重新遍历全文，长文本直接卡 200ms+：

tsx
function highlight(text: string, keyword: string) {
  if (!keyword) return text;
  const parts = text.split(new RegExp(`(${keyword})`, 'gi')); // 全文 split
  return parts.map((p, i) =>
    p.toLowerCase() === keyword.toLowerCase()
      ? <mark key={i}>{p}</mark>
      : <span key={i}>{p}</span>,
  );
}

// 每次输入 keyword，整篇文档重新 split + 重建 React 元素树
export function DocView({ text }: { text: string }) {
  const [keyword, setKeyword] = useState('');
  return <div>{highlight(text, keyword)}</div>;
}

import { useEffect, useRef, useState, useTransition } from 'react';

interface Chunk { text: string; match: boolean; }

export function DocView({ text }: { text: string }) {
  const [keyword, setKeyword] = useState('');
  const [chunks, setChunks] = useState<Chunk[]>([{ text, match: false }]);
  const [isPending, startTransition] = useTransition();
  const workerRef = useRef<Worker | null>(null);
  const reqId = useRef(0);

  useEffect(() => {
    workerRef.current = new Worker(new URL('./highlight.worker.ts', import.meta.url));
    workerRef.current.onmessage = (e) => {
      // 只采纳最新请求的结果，丢弃过期响应
      if (e.data.id !== reqId.current) return;
      startTransition(() => setChunks(e.data.chunks));
    };
    return () => workerRef.current?.terminate();
  }, []);

  const onKeywordChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value;
    setKeyword(value); // 紧急：输入框立即更新
    const id = ++reqId.current;
    workerRef.current?.postMessage({ id, text, keyword: value }); // 重计算丢给 Worker
  };

  return (
    <div>
      <input value={keyword} onChange={onKeywordChange} placeholder="搜索关键词" />
      {isPending && <span className="muted">高亮中…</span>}
      <article>
        {chunks.map((c, i) =>
          c.match ? <mark key={i}>{c.text}</mark> : <span key={i}>{c.text}</span>,
        )}
      </article>
    </div>
  );
}

报表导出、数据透视、批量校验这类"拿到几万条数据后在前端计算"的场景，反面写法是在点击按钮后同步跑 reduce/map 链，主线程被占满，按钮点击后整个页面假死好几秒：

async function onExport() {

  const report = data
    .filter((r) => r.status === 'active')
    .map((r) => ({ ...r, tax: r.amount * 0.13 }))
    .reduce((acc, r) => {
      acc[r.department] = (acc[r.department] ?? 0) + r.amount;
      return acc;
    }, {});
  downloadCSV(report);
  setLoading(false);
}

常见误区 ​

  • will-change: transform 加到所有元素上：显存爆炸，合成开销反而上升。只给即将动画的少数元素加
  • 动画用 left/top 而不是 transform：每帧重排，移动端直接掉帧
  • setInterval 做动画：不与绘制对齐，高刷屏上跑太快、掉帧时堆任务
  • 滚动监听不加 passive：浏览器等 JS 执行完才滚动，体感卡顿
  • 以为 useMemo 能救大列表：记忆化只省重渲染，不省首次渲染的 DOM 创建成本，该上虚拟化就上虚拟化
  • 白屏就怪网络：先看 Console 有没有 hydration 报错，再看 Performance 时间线，别猜

小结 ​

  • 浏览器渲染分 Layout → Paint → Composite 三步；动画只用 transform/opacity 走合成层，是 GPU 加速的核心
  • will-change 与 contain 做渲染隔离，但都不能滥用；translateZ(0) 是层提升的兜底 hack
  • 帧预算 16ms，长任务（>50ms）是 INP 杀手，用 scheduler.yield 拆分、Web Worker 卸载、虚拟化减少 DOM
  • React 并发的 useTransition/useDeferredValue 让重渲染不阻塞输入，但不替代真正的计算优化
  • 白屏按阶段分七类，每类根因和解法不同；标准排查动作是 Network → Console → Performance
