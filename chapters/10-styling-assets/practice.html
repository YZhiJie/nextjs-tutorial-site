场景：一篇要能被搜索与社交分享的文章页 ​

第 8 章的博客解决了「内容怎么渲染」，本篇解决「内容怎么被看到」：

  • 品牌字体全站统一、零外部请求
  • 文章页标题/描述/封面随文章动态变化，社交平台抓取时有 OG 卡片
  • 搜索引擎要能发现全部文章（sitemap）与抓取规则（robots）
  • 首屏 LCP 图片不拖慢性能分

这些对应四组文件约定，全文只动以下文件：

文件职责关键导出
src/app/layout.tsx字体变量、全局标题模板、metadataBasemetadata、viewport
src/app/blog/[slug]/page.tsx动态元数据与封面图渲染generateMetadata、页面组件
src/app/blog/[slug]/opengraph-image.tsxJSX 生成 1200×630 社交图默认导出 + size
src/app/sitemap.ts、src/app/robots.ts公开 URL 清单与抓取规则默认导出

第一步：root layout 定基调 ​

tsx
import type { Metadata, Viewport } from 'next';
import { Geist } from 'next/font/google';
import './globals.css';

const geist = Geist({ subsets: ['latin'], variable: '--font-geist-sans' });

export const metadata: Metadata = {
  metadataBase: new URL('https://example.com'), // 相对路径的 OG 图基于它解析为绝对 URL
  title: { default: '技术札记', template: '%s | 技术札记' }, // 子页只给短标题
  description: '关于 Next.js 与 Web 平台的实践记录',
};

// 16：viewport 相关字段已从 metadata 中分离
export const viewport: Viewport = {
  width: 'device-width',
  initialScale: 1,
  themeColor: '#1d6ff2',
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="zh-CN" className={geist.variable}>
      <body>{children}</body>
    </html>
  );
}

第二步：文章页动态 Metadata + 封面 ​

tsx
import type { Metadata } from 'next';
import Image from 'next/image';
import { notFound } from 'next/navigation';
import { getPost } from '@/lib/posts';

// 16：props（含 params）是 Promise，await 后使用
export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>;
}): Promise<Metadata> {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) return {}; // 交给页面的 notFound() 处理
  return {
    title: post.title, // 自动套上 root layout 的 template
    description: post.excerpt,
    openGraph: {
      type: 'article',
      title: post.title,
      description: post.excerpt,
      images: [`/blog/${slug}/opengraph-image`], // 命中第三步的文件约定
    },
  };
}

export default async function PostPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) notFound();

  return (
    <article>
      <h1>{post.title}</h1>
      <Image src={post.coverUrl} alt={post.coverAlt} width={1200} height={630}
        preload // 16 新名（旧 priority 已废弃）；首屏封面是 LCP 候选
        sizes="(max-width: 768px) 100vw, 720px" />
      <div>{post.content}</div>
    </article>
  );
}

第三步：用 JSX 生成 OG 图 ​

不用设计师逐张出图：在文章段放一个 opengraph-image.tsx，用 next/og 的 ImageResponse 把标题渲染成 1200×630 PNG（底层为 satori/resvg），社交爬虫抓取上面 metadata 声明的地址时自动生成：

tsx
import { ImageResponse } from 'next/og';
import { getPost } from '@/lib/posts';

export const size = { width: 1200, height: 630 };
export const contentType = 'image/png';

// 16：图片生成函数收到的 props 同样是 Promise
export default async function OGImage({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  const post = await getPost(slug);

  return new ImageResponse(
    (
      <div
        style={{
          width: '100%', height: '100%', display: 'flex',
          flexDirection: 'column', justifyContent: 'space-between',
          background: 'linear-gradient(135deg, #0f172a, #1e3a8a)',
          color: 'white', padding: 80, fontSize: 56, fontWeight: 700,
        }}
      >
        <div>{post?.title ?? '技术札记'}</div>
        <div style={{ fontSize: 28, opacity: 0.7 }}>example.com</div>
      </div>
    ),
    size
  );
}

第四步：sitemap 与 robots ​

文件约定零路由代码。文章量大时用 generateSitemaps 分片（返回 [{ id }] 列表，默认导出接收对应 id 渲染那一片）：

ts
import type { MetadataRoute } from 'next';
import { getPostSlugs } from '@/lib/posts';

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const slugs = await getPostSlugs();
  const posts = slugs.map((slug) => ({
    url: `https://example.com/blog/${slug}`,
    changeFrequency: 'weekly' as const,
    priority: 0.8,
  }));

  return [
    { url: 'https://example.com/', priority: 1 },
    { url: 'https://example.com/blog', changeFrequency: 'daily', priority: 0.9 },
    ...posts,
  ];
}

抓取规则放 src/app/robots.ts（同样默认导出，类型 MetadataRoute.Robots）：rules 里对所有 UA allow: '/'、disallow: ['/dashboard', '/api']，并在 sitemap 字段写上上面的 sitemap 绝对地址，无需额外路由代码。

动态 metadata 与缓存

Cache Components 下 generateMetadata 与页面正文应复用同一个 'use cache' 数据函数（配合 React cache() 去重），元数据与文章内容只查一次；需要请求时信息的元数据用第 8 章讲的「动态标记组件」模式。爬虫对流式 HTML 的支持有限，必要时通过 htmlLimitedBots 控制哪些 UA 拿到完整缓冲输出。

最佳实践清单 ​

  • [ ] root layout 必设 metadataBase 与 title.template，页面只写短标题
  • [ ] viewport 三件套用独立的 export const viewport，不要再塞进 metadata
  • [ ] 每篇内容都有唯一 description；OG type 用 article/website 区分
  • [ ] LCP 图加 preload（16 新名）+ 正确 sizes；远程封面确认在 remotePatterns 白名单内
  • [ ] OG 图 1200×630、文字在 56px 以上且避开右下平台水印区
  • [ ] sitemap 只列可索引的公开 URL，/dashboard、/api 进 robots disallow
  • [ ] 动态 OG/metadata 的取数与页面共享缓存函数，避免重复查询

发布前 SEO 检查 ​

  • [ ] 查看源代码（非 DevTools Elements）能看到 <title>、description、OG 标签在服务端 HTML 中
  • [ ] 社交调试工具抓取文章 URL 能显示卡片图与标题
  • [ ] /sitemap.xml、/robots.txt 可直接访问且地址正确
  • [ ] Lighthouse/PageSpeed 下 LCP 图无多余下载尺寸，CLS 为 0
  • [ ] 不存在的 slug 返回 404 状态码而不是软 200
  • [ ] 字体为同源请求，无对字体 CDN 的外部连接

小结与下一步 ​

  • 品牌化文章页 = root layout 字体与 metadataBase + 页面 generateMetadata + opengraph-image.tsx 动态出图 + sitemap.ts/robots.ts
  • viewport 字段独立导出；LCP 图 preload 与 sizes 决定性能分；动态元数据与页面共享缓存取数
  • 服务端 HTML 中能看到标签、调试工具能出卡片、sitemap 可访问，是三项最终验收标准

至此第 6–10 章的核心链路已经闭合：即时导航 → Server Actions → 渲染模型 → 代理与端点 → 静态资产与 SEO。后续章节将进入测试与质量保障：用 @next/playwright 的 instant() 断言导航体验，把前面所有「体感」变成可回归的自动化用例。
