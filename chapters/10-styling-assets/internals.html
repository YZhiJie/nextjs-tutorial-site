本页目录

一个页面的 <head> 有三个来源 ​

10.2 讲了怎么用 Metadata 类型声明标题、描述与 OG 卡；10.3 又把它们跑进了真实文章页。但没有解释：一个页面同时有 root layout、深层 layout、page 三层，每个 metadata 对象都写着 title，最后浏览器里那一个 <title> 到底是谁写的？

真实实现里有三层来源，按由外到内依次累加：

  1. layout 层：每层 layout 的 metadata 导出
  2. page 层：页面自己的 metadata 导出
  3. 静态文件层：icon.svg、apple-icon.png、opengraph-image.tsx 等约定文件自动注入

累加不是「谁在后面谁赢」这么简单——它按字段合并，而不同字段的规则并不一样。这套规则写在 metadata 解析器里，读源码比读文档更清楚。

规则一：顶层字段整体替换，而不是深合并 ​

解析器的入口函数叫 mergeMetadata：先把上一层累积出的结果克隆一份，再遍历当前层的 metadata，按 key 分派处理。

三件事一眼可见：

  • structuredClone(resolvedMetadata)——累加是不可变的：每一层都产出一份新对象，父层的结果不被就地修改

读法：

  • 字符串标题：套用上层传来的 stashedTemplate，template.replace(/%s/g, title)——%s 是占位符，不是 {title}
  • 对象 + default：default 作为本层标题参与模板替换；template 只是「给更深层用」的声明

手写：约 70 行的合并器与序列化器 ​

把上面三条规则落成代码，再加上把累积结果变成 <head> 里的标签：

ts
type Title = string | { default?: string; template?: string; absolute?: string };
type OpenGraph = { title?: string; description?: string; images?: string[] };
type Metadata = {
  title?: Title;
  description?: string;
  openGraph?: OpenGraph;
  alternates?: { canonical?: string };
};

/** 累积结果：title 被解析成一个带 template 残值的对象，供更深层使用 */
type Resolved = {
  title: { absolute: string; template: string | null };
  description?: string;
  openGraph?: OpenGraph;
  alternates?: { canonical?: string };
};

const escapeHtml = (s: string) =>
  s.replace(/[&<>"]/g, (c) => ({ '&': '&', '<': '<', '>': '>', '"': '"' }[c] as string));

const applyTemplate = (template: string | null, title: string) =>
  template ? template.replace(/%s/g, title) : title;

function resolveTitle(title: Title | undefined, stashed: string | null) {
  const ownTemplate = typeof title === 'object' && title ? (title.template ?? null) : null;
  let absolute = '';
  if (typeof title === 'string') {
    absolute = applyTemplate(stashed, title);          // 字符串：套上层模板
  } else if (title) {
    if (title.absolute) absolute = title.absolute;      // absolute：绕过模板
    else if (title.default) absolute = applyTemplate(stashed, title.default);
  }
  return { absolute, template: ownTemplate };
}

/** 顶层字段整体替换：title 走模板解析，其余字段直接覆盖 */
function merge(parent: Resolved, child: Metadata): Resolved {
  const next = structuredClone(parent);
  for (const key of Object.keys(child) as (keyof Metadata)[]) {
    if (key === 'title') {
      next.title = resolveTitle(child.title, parent.title.template);
      if (typeof child.title === 'object' && child.title?.template) {
        next.title.template = child.title.template;     // 交给更深层
      }
    } else if (key === 'description' || key === 'openGraph' || key === 'alternates') {
      next[key] = structuredClone(child[key]) as never; // 浅合并：整体替换
    }
  }
  return next;
}

const accumulate = (layers: Metadata[]) =>
  layers.reduce<Resolved>(
    (acc, layer) => merge(acc, layer),
    { title: { absolute: '', template: null } },
  );

function headTags(m: Resolved): string[] {
  const tags: string[] = [];
  if (m.title.absolute) tags.push(`<title>${escapeHtml(m.title.absolute)}</title>`);
  if (m.description)
    tags.push(`<meta name="description" content="${escapeHtml(m.description)}">`);
  if (m.alternates?.canonical)
    tags.push(`<link rel="canonical" href="${m.alternates.canonical}">`);
  if (m.openGraph?.title)
    tags.push(`<meta property="og:title" content="${escapeHtml(m.openGraph.title)}">`);
  for (const img of m.openGraph?.images ?? [])
    tags.push(`<meta property="og:image" content="${img}">`);
  return tags;
}

/* ---------- 用法 ---------- */
const resolved = accumulate([
  { title: { template: '%s | TeamHub', default: 'TeamHub' }, description: '团队协作台' },
  { title: '账单' },
]);
console.log(resolved.title.absolute);        // 账单 | TeamHub
console.log(headTags(resolved).join('\n'));  // <title>…</title> / <meta …>

三个真实踩坑现场 ​

::: warn 最深的一层声明 openGraph，父级的一切 OG 字段都会消失。分享卡片的标题、描述、图片分别来自不同层时，务必在同一层把 openGraph 写全；或者干脆把整站 OG 配置收敛到一个模块里，各页面只覆盖 title。 :::

DANGER

title.template 写在 page 里不生效。模板只能向下传播，而 page 是最底层。想要「页面标题自动带站点后缀」，模板必须声明在比它更外层的 layout 上；某页确实不想要后缀时，用 title: { absolute: '…' } 显式绕过，而不是去写一个空模板。

TIP

metadataBase 决定相对 URL 的命运。OG 图、canonical 这些带 URL 的字段，若写相对路径就必须有 metadataBase 兜底，否则构建期直接报错；线上用的绝对域名也应该写在 metadataBase 里，而不是散落在每个页面。

自测

root layout 声明 title: { template: '%s | TeamHub', default: 'TeamHub' }。子页面 A 写 title: '账单'，子页面 B 写 title: { absolute: '账单' }。两者渲染出的 <title> 分别是什么？

小结 ​

  • <head> 由三层来源累加：layout → page → 静态文件，逐层产出一份新的解析结果
  • 合并粒度是顶层字段：子级的 openGraph/alternates 会整体替换父级，不做深合并
  • title 是唯一带模板语义的字段：字符串套 %s 模板，default 参与替换，absolute 绕过模板
  • title.template 只向更深层传播，写在 page 上等于白写
  • 序列化只是把解析结果摊平成标签，真正的复杂度全在「谁覆盖谁」上
