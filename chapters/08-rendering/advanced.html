渲染哲学：静态与动态是一条光谱 ​

大多数框架把「静态/动态」画成路由级的硬边界：一个页面要么构建期生成，要么请求期生成。Next.js 的模型把边界下沉到组件级：同一个响应里，静态外壳瞬时到达，缓存函数独立再生，动态区域流式补入——这正是 Cache Components 与流式渲染共同实现的形态。

模型静态/动态边界位置代价
构建期预渲染整个应用基础设施零成本，任何改动要重发版
路由级二选一每条路由一页里一个动态元素就得整页动态
组件级光谱（Next 16）组件树中的每个 await需要流式、缓存协调等平台能力配合

15 时代的实验特性 PPR（Partial Prerendering）在 16 中已被收编进 Cache Components：experimental.ppr 与段配置 experimental_ppr 均已移除，开启 cacheComponents: true 即获得等价能力，还有官方 codemod 负责删除旧配置。

Cache Components 时代的 ISR ​

开启 cacheComponents（以及配套的 partialPrefetching）后，动态段的预渲染语义变成两段：

  • App Shell：不依赖 URL 数据的通用外壳，任何未预渲染路径都能立即拿到它
  • 参数化预渲染：generateStaticParams 列出的路径，连参数相关内容一起生成

未列出的路径首次访问时：先服务外壳（参数区域显示 Suspense 回退）→ 已知参数后在后台升级为完整页面 → 后续访问直接命中升级产物。连第一次预取（<Link> 进入视口）都算「首次访问」，升级在用户点击前就开始了。

tsx
import { Suspense } from 'react';
import { PostBody, PostSkeleton } from './post-body';

// Cache Components 下必须返回至少一组参数（空数组会报 empty-generate-static-params）
// 只预渲染最热的一篇，其余路径靠外壳 + 后台升级
export async function generateStaticParams() {
  const posts = await getPostList();
  return posts.slice(0, 1).map((post) => ({ slug: post.slug }));
}

// 页面不 await params，外壳不绑定任何具体 URL
export default function BlogPostPage({ params }: { params: Promise<{ slug: string }> }) {
  return (
    <Suspense fallback={<PostSkeleton />}>
      <PostBody params={params} />
    </Suspense>
  );
}

访问路径经典 ISRCache Components ISR

预取行为不触发升级进入视口即开始后台升级

connection()：声明式软动态 ​

有些代码不碰任何请求时 API，却必须按请求产生不同结果：Math.random()、new Date()，或者 better-sqlite3 这类同步数据库驱动。在 Cache Components 下，预渲染执行到这类调用会直接构建报错——因为框架无法判断它该在什么时候跑。

connection() 就是显式的分界标记：「预渲染在此停止，以下代码请求时才执行」：

ts
import { connection } from 'next/server';
import Database from 'better-sqlite3';

const db = new Database('app.db');

export async function getVisitorCount() {
  await connection(); // 预渲染到此为止；调用方组件应包在 Suspense 内
  return db.prepare('SELECT value FROM counters WHERE name = ?').get('visitors');
}

动态兜底：not-found 与错误 ​

未预渲染路径查不到数据时，notFound() 会渲染最近的 not-found.tsx，状态码为 404；它可以在异步组件、Action、Route Handler 中任意位置调用：

tsx
import { notFound } from 'next/navigation';

export async function PostBody({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) {
    notFound(); // 渲染最近的 not-found.tsx，等价于过去的 dynamicParams: false 拒绝
  }
  return <article>{/* … */}</article>;
}

generateMetadata 的动态化 ​

元数据遵循同样规则。generateMetadata 中读取外部数据应加 'use cache'；若元数据本身依赖请求时信息（无法用 Suspense 包裹 metadata），官方模式是在页面放一个「动态标记组件」（内部 await connection()），让静态内容照常预渲染、元数据随请求流入。第 10 章会给出完整代码。

View Transitions：导航的原生过渡 ​

渲染模式之外，React 19.2 提供与浏览器 View Transitions API 集成的 <ViewTransition> 组件（从 react 直接导入）。Next.js 的路由导航本身就是一次 transition，因此给「列表缩略图」和「详情大图」套上同名边界，浏览器会自动在旧位置与新位置之间做形变动画：

tsx
import { ViewTransition } from 'react';
import Link from 'next/link';
import Image from 'next/image';

export function PhotoThumb({ photo }: { photo: { id: string; src: string; alt: string } }) {
  return (
    <Link href={`/photo/${photo.id}`}>
      {/* 列表图与详情页的大图使用相同的 name，即共享同一视觉元素 */}
      <ViewTransition name={`photo-${photo.id}`}>
        <Image src={photo.src} alt={photo.alt} width={200} height={200} />
      </ViewTransition>
    </Link>
  );
}

渐进增强，不支持就静默

View Transitions 需要较新的 Chromium/Safari/Firefox 版本；不支持的浏览器里应用照常工作，只是没有动画。Suspense 解析与 useDeferredValue 也会触发该组件的过渡，可用于骨架屏到真实内容的淡入。

选型建议：什么时候停在经典模型 ​

Cache Components 不是必选项。官方仍完整维护未开启时的模型（revalidate、fetch 缓存选项、caching-without-cache-components 指南）。若项目满足以下全部条件，经典 ISR 依然是低成本好选择：内容型页面为主、没有即时导航诉求、自托管且暂无 cache handler 基础设施。新页面或追求导航体感的产品，则直接按第 6 章的路径接入 Cache Components。

小结 ​

  • 16 的渲染边界在组件级：PPR 已被 Cache Components 收编，experimental.ppr 彻底移除
  • Cache Components ISR = 子集预渲染 + 即时外壳 + 后台升级；generateStaticParams 必须非空、params 要在 Suspense 内 await
  • connection() 标记软动态分界，notFound() 承担动态兜底；View Transitions 提供零依赖的导航形变且自动渐进增强
