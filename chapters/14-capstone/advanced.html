模块一：租户布局与身份 UI ​

铁律延续第 11 章：布局顶层不 await 会话，否则整个租户段（含 {children}）被请求读取挡住。身份相关 UI 沉到 Suspense 边界内：

tsx
import { Suspense } from 'react';
import { TenantSidebar } from './tenant-sidebar';
import { UserMenu } from './user-menu';

export default function TenantLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="tenant-shell">
      <TenantSidebar /> {/* 静态外壳：导航结构立即可见，不读会话 */}
      <header>
        {/* 只有右上角菜单等会话，放进边界，不阻塞 children 首字节 */}
        <Suspense fallback={<span className="muted">…</span>}>
          <UserMenu />
        </Suspense>
      </header>
      {children}
    </div>
  );
}

模块二：列表 → 详情的即时导航 ​

项目详情是高频入口，值得 URL 级预取；侧边栏的 50 个项目链接则保留默认外壳预取，控制服务端调用量：

tsx
import Link from 'next/link';

export function ProjectList({ featured, projects }: ProjectListProps) {
  return (
    <ul>
      {projects.map((p, i) => (
        <li key={p.id}>
          {/* 仅精选首条付预取成本：每链一次服务端调用 */}
          <Link
            href={`/t/${p.tenantId}/projects/${p.id}`}
            prefetch={i === 0 && featured}
          >
            {p.name}
          </Link>
        </li>
      ))}
    </ul>
  );
}

模块三：Action 变更与标签失效 ​

所有写操作遵循同一形状：Action 内重新取会话（不信闭包之外的身份）→ DAL 做归属校验与落库 → updateTag 让写后立即失效：

ts
'use server';

import { revalidatePath } from 'next/cache';
import { updateTag } from 'next/cache';
import { getTenantContext } from '@/lib/tenant-dal';
import { renameProject } from '@/lib/project-dal';

export async function renameProjectAction(projectId: string, name: string) {
  const { tenantId } = await getTenantContext();       // ① 重新认证+租户上下文
  await renameProject({ tenantId, projectId, name });  // ② DAL 内校验归属
  updateTag(`tenant:${tenantId}:projects`);            // ③ 写后立即失效
  revalidatePath(`/t/${tenantId}/projects`);           // 兼容未迁移段
}

埋点、通知这类“不阻塞响应”的善后用 after()：响应返回后执行，不拖慢用户感知，也不占渲染期（渲染期禁止副作用）。

模块四：SEO——metadata 模板与 JSON-LD ​

营销与博客是获客入口。用 metadata 模板保证标题体系一致，用 JSON-LD 让搜索引擎与 AI 理解内容。注意 JSON 串化必须转义 <，防止注入：

tsx
import type { Metadata } from 'next';

export async function generateMetadata({ params }: PageProps<'/blog/[slug]'>): Promise<Metadata> {
  const { slug } = await params;
  const post = await getPublishedPost(slug);
  return {
    title: post.title, // 自动套上 layout 中 title.template："%s | TeamHub"
    alternates: {
      canonical: `/blog/${slug}`,
      languages: { 'zh-CN': `/zh-CN/blog/${slug}`, 'en-US': `/en-US/blog/${slug}` },
    },
  };
}

export default async function PostPage({ params }: PageProps<'/blog/[slug]'>) {
  const { slug } = await params;
  const post = await getPublishedPost(slug);
  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'BlogPosting',
    headline: post.title,
    datePublished: post.publishedAt,
    author: { '@type': 'Organization', name: 'TeamHub' },
  };
  return (
    <article>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }}
      />
      {/* 正文 */}
    </article>
  );
}

模块六：让 AI 智能体成为“按文档干活的同事” ​

16.4 专门为 AI 编程工作流铺了一条链路。它不是噱头，而是对抗“模型记忆停在旧版 Next”的工程手段：

能力载体你要做的
版本匹配文档node_modules/next/dist/docs/确保智能体读随包文档而非训练记忆
项目规则AGENTS.md 自动托管块next dev 检测到智能体时自动 upsert，勿删托管块
多步工作流first-party Skills（如缓存组件迁移技能）把“迁移 cacheComponents”这类成流程任务交给对应 Skill
运行时可见性next-devtools-mcp（MCP）在 .mcp.json 注册，智能体可读构建错误、组件树与日志
在线文档任意 docs URL 追加 .md、/docs/llms.txt让只支持联网抓取的智能体也拿到 Markdown 版

项目根目录放一个 .mcp.json，在 mcpServers.next-devtools 下注册（command: "npx"，args: ["-y", "next-devtools-mcp@latest"]），智能体即可通过 MCP 读取运行时信息。

AGENTS.md 的托管块由 next dev 自动维护，团队自己的规范写在标记块外面即可保留：

md
# 团队工程规范（手写区，升级不会丢）
- 所有 DAL 函数必须接收租户上下文
- Action 命名统一以 Action 结尾

<!-- BEGIN:nextjs-agent-rules -->
# This is NOT the Next.js you know
# Read the relevant guide in node_modules/next/dist/docs/ ...
<!-- END:nextjs-agent-rules -->

小结 ​

  • 六大模块各自复用前序章节：身份下沉 Suspense、链接分级预取、Action 三段式、metadata+JSON-LD、三层可观测、AI 链路
  • updateTag 让写操作立即生效；after() 承担不阻塞响应的善后
  • AGENTS.md + Skills + DevTools MCP 让智能体按 16.4 的真实规则协作，但门禁不变
