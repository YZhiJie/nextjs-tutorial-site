本页目录

app 目录即路由 ​

App Router 没有集中式的路由配置文件。文件夹就是 URL 段，约定文件就是该段的 UI。在 src/app/ 下每新建一个文件夹加一个 page.tsx，就得到一条可访问路由：

text
src/app/
├── page.tsx                  # /
├── blog/
│   └── page.tsx              # /blog
│       └── [slug]/
│           └── page.tsx      # /blog/:slug（动态段）
└── dashboard/
    └── page.tsx              # /dashboard

只有名叫 page 的文件才会成为可访问 URL 的叶子；layout、loading、error 等文件服务于该段但不产生独立路径。

page、layout、template：三种共享 UI 的区别 ​

约定文件作用导航时是否重渲染/重挂载
page.tsx路由叶子，对应一个具体 URL切换路由时渲染新页面
layout.tsx包裹子段的共享 UI，接收 children不重渲染，状态保留
template.tsx与 layout 结构相同，但带唯一 key该段每次导航都重新挂载

根布局是必需的，且必须包含 <html> 与 <body>：

tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: 'Next.js 16.3 练功房',
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="zh-CN">
      <body>{children}</body>
    </html>
  );
}

在 blog/ 下再加一个同名 layout.tsx，它会自动包住 /blog 与 /blog/[slug] 两个页面——写法与根布局相同：默认导出接收 children 的组件，把侧边栏、子导航放在 {children} 之外即可，嵌套层级由目录结构自动决定。

TIP

布局不重渲染意味着：布局里的客户端状态（搜索框文字、侧边栏展开状态）在子页面间切换时天然保留。需要“每次进入都重置”的 UI（例如录入表单、进场动画）才用 template.tsx。

用 Link 导航，而不是手写 a 标签 ​

<Link> 是对 <a> 的封装，提供客户端跳转与视口内自动预取：链接滚入视口后，Next.js 会在后台预取目标路由，点击时往往无需等待网络。

tsx
import Link from 'next/link';

type Post = { slug: string; title: string };

export default function PostList({ posts }: { posts: Post[] }) {
  return (
    <ul className="space-y-2">
      {posts.map((post) => (
        <li key={post.slug}>
          <Link href={`/blog/${post.slug}`} className="text-blue-600">
            {post.title}
          </Link>
        </li>
      ))}
    </ul>
  );
}

需要编程式导航（提交成功后跳转、按钮触发）时，在客户端组件里使用 next/navigation 的 useRouter；读取当前路径用 usePathname：

  • router.push(href)：新增一条历史记录并跳转
  • router.replace(href)：替换当前历史记录（登录后常用）
  • router.back() / router.forward()：历史前进后退

::: warn 预取只在生产环境生效，pnpm dev 下观察不到预取请求是正常的。静态路由默认预取整页；动态路由默认跳过，或在该段存在 loading.tsx 时预取共享布局与骨架。 :::

动态段：params 必须 await ​

方括号文件夹 [slug] 捕获 URL 中的动态值。16.x 中 params 是一个 Promise，必须 await 后解构：

tsx
import { notFound } from 'next/navigation';
import { getPost } from '@/lib/posts';

// 用全局 PageProps 类型约束 params 形状
export default async function BlogPostPage(
  props: PageProps<'/blog/[slug]'>
) {
  const { slug } = await props.params; // 16.x：params 是 Promise
  const post = await getPost(slug);

  if (!post) {
    notFound(); // 数据不存在时渲染该段的 not-found.tsx
  }

  return (
    <article>
      <h1>{post.title}</h1>
      <div>{post.content}</div>
    </article>
  );
}

查询字符串同理：页面组件的 searchParams 也是 Promise，const { q } = await searchParams。读取 searchParams 会让该页进入动态渲染，因为它依赖真实请求。

DANGER

从 15 升级的项目最典型的运行时错误就是漏写 await：params.slug 取到的是 undefined。同段的 layout.tsx、generateMetadata、route.ts 拿到的 params 也全是 Promise。

loading / error / not-found：三个约定文件 ​

这三个文件分别接管一段路由的“加载中、出错了、找不到”三种状态，框架会自动把它们包成对应的 React 边界。

tsx
export default function Loading() {
  return (
    <div className="animate-pulse space-y-3">
      <div className="h-8 w-2/3 rounded bg-gray-200" />
      <div className="h-4 w-full rounded bg-gray-200" />
      <div className="h-4 w-5/6 rounded bg-gray-200" />
    </div>
  );
}

error.tsx 必须是客户端组件，16.3 的恢复函数叫 retry（旧版的 reset 仍可用，但只重置错误状态、不重新取数）：

tsx
'use client';

import { useEffect } from 'react';

export default function BlogError({
  error,
  retry,
}: {
  error: Error & { digest?: string };
  retry: () => void;
}) {
  useEffect(() => {
    // 上报到错误监控；服务端错误的 message 会被脱敏，用 digest 对日志
    console.error(error.digest, error.message);
  }, [error]);

  return (
    <div>
      <h2>文章加载失败</h2>
      <button onClick={() => retry()} className="primary">
        重试
      </button>
    </div>
  );
}

not-found.tsx 是普通服务端组件，无需接收 props：在同段放一个返回“没有这篇文章 + 返回列表”链接的默认导出，就会接管 notFound() 与该段的 404 展示。

错误会沿路由树向上冒泡到最近的 error.tsx，所以可以在根段放粗粒度兜底、在重要业务段放细粒度提示。

常见误区 ​

  • 在服务端组件里用 useRouter：导航 hook 只能在客户端组件中调用；服务端需要跳转请用 redirect()。
  • 把 <a href> 当主用导航：原生 <a> 会整页刷新，不预取、不保留布局状态；只有跳外链才用它。
  • 布局里直接 await params 导致整段无法预渲染：进阶篇与第 5、6 章会给出“把 params Promise 下发到子组件”的模式。
  • 以为 loading.tsx 能救布局里的慢数据：同段 loading.tsx 包不住同段布局的异步阻塞，慢取数要下沉到 page 或用 <Suspense> 就近包裹。

小结 ​

  • App Router 用文件系统约定路由：文件夹是 URL 段，page.tsx 是叶子
  • layout 导航时不重渲染、状态保留；template 每次重挂载
  • <Link> 提供客户端跳转与视口预取，usePathname/useRouter 服务于交互场景
  • 动态段与查询参数在 16.x 全是 Promise，一律 await
  • loading/error/not-found 三个约定文件把加载、错误、404 边界化
