场景：一个域名，两套外壳 ​

假设我们要做一个 SaaS 产品站：/、/pricing 等营销页要透明导航、大按钮、无登录态；/dashboard、/dashboard/orders/[id] 等应用区要固定侧边栏、面包屑、需要登录；订单详情还要能在列表上“侧滑打开”，直达 URL 又是完整页。如果用一套根布局，营销页就得反复“隐藏侧边栏”——正确做法是用路由组让两区域各持根布局，再用并行 + 拦截路由承接详情弹层。

text
src/app/
├── (marketing)/
│   ├── layout.tsx               # 营销根布局（无侧边栏）
│   ├── page.tsx                 # /
│   └── pricing/page.tsx         # /pricing
├── (app)/
│   ├── layout.tsx               # 应用外壳：侧边栏 + 顶栏
│   └── dashboard/
│       ├── page.tsx
│       └── orders/[id]/
│           ├── layout.tsx       # 详情段布局：面包屑
│           └── page.tsx
├── @drawer/
│   ├── default.tsx              # 默认不渲染弹层
│   └── (.)dashboard/orders/[id]/page.tsx
└── …（global-error.tsx、not-found.tsx 放根段）

INFO

拦截目录写在 @drawer slot 内，用 (.)dashboard 表示“在与 slot 同级的根段上拦截 dashboard”，再接 orders/[id]。记住匹配按路由段计算、@drawer 不占段。

落地步骤 ​

::: steps

  1. 建 (marketing) 与 (app) 两组，各自补 layout.tsx，把原顶层 page.tsx 移入营销组
  2. 应用组外壳中放置侧边栏导航与顶栏，子页面通过 {children} 注入
  3. 在 dashboard/orders/[id]/layout.tsx 中实现面包屑，随动态段自动更新
  4. 增加 @drawer slot 与 default.tsx，在订单列表用拦截路由打开详情
  5. 补段级 error.tsx、根级 not-found.tsx 与 global-error.tsx，手测组内/跨组/弹层三条路径 :::

第一步：应用组外壳与激活导航 ​

导航数据用“段前缀”描述，激活判断用 usePathname()，父级菜单在子路由下也能高亮：

tsx
'use client';

import Link from 'next/link';
import { usePathname } from 'next/navigation';

const NAV_ITEMS = [
  { href: '/dashboard', label: '概览' },
  { href: '/dashboard/orders', label: '订单' },
];

export default function AppSidebar() {
  const pathname = usePathname();

  return (
    <nav className="flex w-56 flex-col gap-1 p-3">
      {NAV_ITEMS.map((item) => {
        // 精确命中首页，其余前缀匹配，保证子路由高亮父菜单
        const active =
          item.href === '/dashboard'
            ? pathname === '/dashboard'
            : pathname.startsWith(item.href);
        return (
          <Link
            key={item.href}
            href={item.href}
            className={`rounded-lg px-3 py-2 text-sm ${
              active ? 'bg-blue-50 font-semibold text-blue-700' : 'text-gray-600'
            }`}
          >
            {item.label}
          </Link>
        );
      })}
    </nav>
  );
}

第二步：面包屑随段更新 ​

把 params Promise 直接传给一个被 Suspense 包住的小标题组件，既保住静态外壳，又能显示当前订单号。注意这个布局要放在 [id] 段目录内，才能拿到 id：

tsx
import Link from 'next/link';
import { Suspense } from 'react';

export default function OrderDetailLayout({ children, params }: LayoutProps<'/dashboard/orders/[id]'>) {
  return (
    <>
      <header className="border-b px-6 py-3 text-sm text-gray-500">
        <Link href="/dashboard">控制台</Link>
        {' / '}
        <Link href="/dashboard/orders">订单</Link>
        <Suspense fallback={<span> / …</span>}>
          {params.then(({ id }) => <span key={id}> / {id}</span>)}
        </Suspense>
      </header>
      {children}
    </>
  );
}

第三步：订单详情的“弹层/整页”双形态 ​

拦截页与完整页复用同一个服务端 OrderDetail，保证两处内容永远一致：

tsx
import { OrderDrawer } from '@/components/order-drawer';
import { OrderDetail } from '@/components/order-detail';

export default async function InterceptedOrder(props: PageProps<'/dashboard/orders/[id]'>) {
  const { id } = await props.params;
  return (
    <OrderDrawer>
      <OrderDetail id={id} />
    </OrderDrawer>
  );
}

关闭弹层不要写自定义路由状态：OrderDrawer 内放一个调用 router.back() 的按钮即可，历史栈天然正确。再补两个 slot 兜底——@drawer/default.tsx 返回 null；若希望导航到任意无关路由都关闭弹层，在 slot 内加 [...catchAll]/page.tsx 返回 null。

第四步：错误与 404 的三层防线 ​

层级文件接管范围
业务段dashboard/orders/error.tsx订单列表/详情崩溃，保留侧边栏与顶栏
全局未捕获global-error.tsx根布局自身崩溃；必须自带 <html>/<body>
找不到资源段内 not-found.tsx + 根 not-found.tsxnotFound() 触发与整站未知 URL

DANGER

global-error.tsx 会替换根布局，所以它必须自己渲染 <html>、<body>，并在文件顶部声明 'use client'。忘了 html 标签会导致整页白屏且没有任何报错边界兜底。

最佳实践清单 ​

  • [ ] URL 先画树形图再落文件夹；(group) 只组织代码与分布局，不承担语义
  • [ ] 一个产品最多两套根布局；跨根布局跳转预期为整页刷新，营销页避免随手链到应用区
  • [ ] 跨页导航统一用 <Link>，外链与下载才用原生 <a>；激活态从 usePathname() 推导
  • [ ] 动态参数一律 await params，布局中把 Promise 下沉到 Suspense 子树
  • [ ] 模态类需求优先“并行 + 拦截路由”，关闭用 router.back()，slot 用 default.tsx/catch-all 兜底
  • [ ] 重要业务段配齐 loading.tsx/error.tsx/not-found.tsx；长链接列表评估 prefetch={false}
