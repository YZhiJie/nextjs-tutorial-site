用路由组切分“看起来不同”的区域 ​

营销页（品牌导航、大留白）和应用内页面（侧边栏、面包屑）通常需要不同的根布局，但又不希望 URL 里多出一段。路由组 (folderName) 正好解决：括号内的文件夹只负责组织代码，不进入 URL。

text
src/app/
├── (marketing)/
│   ├── layout.tsx          # 营销根布局（无侧边栏）
│   ├── page.tsx            # /
│   └── about/page.tsx      # /about
└── (app)/
    ├── layout.tsx          # 应用根布局（侧边栏 + 顶栏）
    ├── dashboard/page.tsx  # /dashboard
    └── settings/page.tsx   # /settings

::: warn 两个规则必须记住：

  • 不同根布局之间跳转会触发整页刷新，因为浏览器要换一整份 HTML 文档
  • 不同组不能解析出相同 URL，例如 (marketing)/about 与 (app)/about 会构建报错

若使用多个根布局且没有顶层 layout.tsx，首页 / 必须落在其中一个组里。 :::

catch-all：一个段吃掉剩余路径 ​

动态段 [slug] 只匹配一级；加省略号 [...slug] 可以吞掉后面所有层级，值变成数组；双方括号 [[...slug]] 则连“零层级”也匹配：

文件写法访问 /shop访问 /shop/a/bparams
shop/[slug]/page.tsx不匹配不匹配{ slug: string }
shop/[...slug]/page.tsx不匹配匹配{ slug: string[] }
shop/[[...slug]]/page.tsx匹配（undefined）匹配{ slug?: string[] }
tsx
import { notFound } from 'next/navigation';

type DocSlug = { slug?: string[] };

export default async function DocsPage(props: PageProps<'/docs/[[...slug]]'>) {
  const { slug } = await props.params;
  // /docs 时 slug 为 undefined；/docs/a/b 时为 ['a', 'b']
  if (!slug) return <h1>文档首页</h1>;

  const doc = await getDocByPath(slug.join('/'));
  if (!doc) notFound();

  return <article>{doc.content}</article>;
}

并行路由：一个布局里同时挂多个页面 ​

@folder 创建一个具名 slot，它不是 URL 段，而是作为 prop 传给父布局，让多个页面在同一视图里独立导航、独立流式、独立报错：

tsx
export default function DashboardLayout({
  children,
  team,
  analytics,
}: LayoutProps<'/dashboard'>) {
  return (
    <div className="grid grid-cols-3 gap-4 p-4">
      <section className="col-span-2">{children}</section>
      <aside className="space-y-4">
        {team}
        {analytics}
      </aside>
    </div>
  );
}

软导航与硬加载的差异是并行路由最容易踩的点：

  • 客户端软导航时，框架只更新匹配的 slot，其他 slot 保持当前子页面（即使与 URL 不完全对应）
  • 浏览器刷新（硬导航）时，框架无法还原不匹配 URL 的 slot，会渲染该 slot 的 default.tsx；没有 default.tsx 就返回 404

DANGER

不要在 slot 布局里用“条件渲染 slot”做权限分流后就以为安全——文档明确指出：两个 slot 的代码都会在服务端执行并随响应下发，条件只决定显示哪个。鉴权必须写进每个 slot 页面内部或数据访问层。

拦截路由：在当前上下文里打开另一条路由 ​

点击信息流里的照片，希望在当前页弹出模态框；但直接访问 /photo/123 或刷新时又应进入完整照片页。拦截路由用相对段约定实现这种“软导航拦截、硬访问放行”：

约定拦截层级
(.)photo同级
(..)photo上一级
(..)(..)photo上两级
(...)photo从 app 根目录算起

(..) 按路由段而非文件系统层级计算，@slot 文件夹不计层级。拦截路由几乎总是与并行路由搭配：把被拦截的页面放进 @modal/(.)photo/page.tsx，模态内容可分享 URL、刷新不丢、浏览器后退即关闭。

tsx
import { Modal } from '@/components/modal';
import { PhotoView } from '@/components/photo-view';

export default async function InterceptedPhoto(
  props: PageProps<'/photo/[id]'>
) {
  const { id } = await props.params;
  return (
    <Modal>
      <PhotoView id={id} />
    </Modal>
  );
}

template 为什么会重挂载 ​

基础篇记住了“layout 不重渲染、template 会”。原理是框架渲染 template 时给它注入按段生成的唯一 key，输出等价于：

text
<Layout>
  <Template key={routeParam}>{children}</Template>
</Layout>
1
2
3

因此段（含动态参数）变化时：内部客户端组件状态重置、useEffect 重新执行、DOM 整体重建；更深层级导航不会重挂高层 template；仅 searchParams 变化也不会重挂。需要“每进一次文章页播放一次进入动画”或“离开即清空表单”，用 template；否则默认 layout。

预取与客户端路由缓存 ​

点击流畅的本质，是导航在点击之前就开始了。预取行为随路由类型与 prefetch 取值变化：

<Link prefetch>静态路由动态路由
null / "auto"（默认）预取完整 RSC 负载跳过，或预取到最近 loading.tsx 边界的外壳
true预取完整路由（含数据）同样预取完整路由
false点击时才请求点击时才请求（悬停也不预取）

长链接列表（无限滚动表格）建议对非首屏链接显式 prefetch={false}，或自行实现“悬停才预取”（悬停时把 prefetch 从 false 切回 null）。

TIP

开启 partialPrefetching 后默认值的含义会变：auto 只预取每条路由的共享 App Shell，prefetch={true} 才做带 URL 数据（params/searchParams）的 URL 级预取。第 6 章会完整拆解这套模型。

滚动恢复 ​

客户端导航默认滚到新页顶部；前进/后退则恢复到之前的滚动位置，行为与浏览器原生文档一致。两个定制点：

  • <Link scroll={false}> 或 router.push(href, { scroll: false })：跳转后保持当前滚动位置（页内嵌详情场景）
  • 固定/吸顶头部遮挡内容时，用 CSS scroll-padding-top 修正恢复位置，而不是手写滚动 JS

小结 ​

  • (group) 只组织文件、不进 URL，可承载多根布局，但跨根布局导航是整页刷新
  • [...slug] 与 [[...slug]] 用数组承接多级路径，注意 undefined 分支
  • @slot 让多页面同屏独立导航，软导航靠内存状态、硬加载靠 default.tsx
  • (.)/(..) 按路由段拦截，配合并行路由实现可分享、可后退的模态
  • 预取按静态/动态与 prefetch 取值分级，滚动恢复默认即可，特殊场景用 scroll={false}
