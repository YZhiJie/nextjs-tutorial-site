场景：一个经得起真实网络的待办 ​

待办是检验全栈数据流最好的最小业务：三类变更（增、改、删）+ 一个列表读取，刚好覆盖本章所有知识点。我们的验收标准：

  • 提交新待办：输入框立即清空、列表乐观出现新项、失败可回滚
  • 勾选完成：UI 即时翻转，服务端确认后与缓存对齐
  • 删除：乐观移除，不打断当前操作
  • 所有变更后列表缓存失效，用户立刻看到自己的操作结果（read-your-own-writes）

第一步：数据层打缓存标签 ​

读取函数缓存列表并打上标签，写操作之后才能精准失效：

ts
import { cacheLife, cacheTag } from 'next/cache';
import { db } from './db';

export type Todo = { id: string; text: string; done: boolean };

export async function getTodos(): Promise<Todo[]> {
  'use cache';
  cacheLife('seconds'); // 列表短期新鲜
  cacheTag('todos');    // 任何写操作都失效这个标签
  return db.todo.findMany({ orderBy: { createdAt: 'desc' } });
}

第二步：三个 Action，每个都鉴权 ​

ts
'use server';

import { revalidatePath, updateTag } from 'next/cache';
import { getSession } from '@/lib/auth';
import { db } from '@/lib/db';

// 统一在写入前确认登录态：Action 可被直接 POST，不能靠 UI 隐藏
async function requireUser() {
  const session = await getSession();
  if (!session?.user) throw new Error('未登录');
  return session.user;
}

export async function addTodo(formData: FormData) {
  const user = await requireUser();
  const text = String(formData.get('text') ?? '').trim();
  if (!text) return;

  await db.todo.create({ data: { text, ownerId: user.id } });

  // 立即失效：响应自带的重渲染会等待新数据，用户马上看到新待办
  updateTag('todos');
  revalidatePath('/todos');
}

export async function toggleTodo(id: string) {
  const user = await requireUser();
  const todo = await db.todo.findFirst({ where: { id, ownerId: user.id } });
  if (!todo) return; // 所有权复核：不存在或不属于本人，静默拒绝

  await db.todo.update({ where: { id }, data: { done: !todo.done } });
  updateTag('todos');
}

export async function deleteTodo(id: string) {
  const user = await requireUser();
  await db.todo.deleteMany({ where: { id, ownerId: user.id } }); // 删除同样带归属条件
  updateTag('todos');
}

为什么用 updateTag 而不是 revalidateTag

待办场景要求「我提交后立刻看见自己的改动」。updateTag 让 Action 响应里那次重渲染等待新数据；revalidateTag('todos', 'max') 是先给旧值、后台刷新，用户会短暂看到自己刚提交的内容「没生效」。后者更适合 Webhook 触发、对实时性不敏感的场景。

第三步：服务端页面 + 客户端交互叶子 ​

页面保持服务端组件，直接 await getTodos()；只把交互部分下放到客户端组件，action 作为 props 传入（可序列化要求只传字符串 id）：

tsx
import { getTodos } from '@/lib/todos';
import { addTodo, toggleTodo, deleteTodo } from './actions';
import { TodoList } from './todo-list';

export default async function TodosPage() {
  const todos = await getTodos(); // 服务端取数，零客户端 JS 拿到首屏
  return (
    <main>
      <h1>我的待办</h1>
      <TodoList
        initialTodos={todos}
        addTodo={addTodo}
        toggleTodo={toggleTodo}
        deleteTodo={deleteTodo}
      />
    </main>
  );
}

第四步：客户端组件组装乐观更新 ​

tsx
'use client';

import { useOptimistic, useRef, useTransition } from 'react';
import type { Todo } from '@/lib/todos';

type Actions = {
  addTodo: (formData: FormData) => Promise<void> | void;
  toggleTodo: (id: string) => Promise<void> | void;
  deleteTodo: (id: string) => Promise<void> | void;
};

export function TodoList({
  initialTodos,
  addTodo,
  toggleTodo,
  deleteTodo,
}: { initialTodos: Todo[] } & Actions) {
  const [optimisticTodos, mutate] = useOptimistic(
    initialTodos,
    // 统一处理三类乐观变更
    (state, change: { type: 'add'; text: string } | { type: 'toggle' | 'delete'; id: string }) => {
      if (change.type === 'add') {
        return [{ id: `temp-${Date.now()}`, text: change.text, done: false }, ...state];
      }
      if (change.type === 'delete') {
        return state.filter((t) => t.id !== change.id);
      }
      return state.map((t) => (t.id === change.id ? { ...t, done: !t.done } : t));
    }
  );
  const [pending, startTransition] = useTransition();
  const formRef = useRef<HTMLFormElement>(null);

  return (
    <>
      <form
        ref={formRef}
        action={(formData) =>
          startTransition(async () => {
            const text = String(formData.get('text') ?? '').trim();
            if (!text) return;
            mutate({ type: 'add', text }); // 先乐观插入
            await addTodo(formData);        // 再等服务端；失败由 error 边界接管回滚
            formRef.current?.reset();
          })
        }
      >
        <input name="text" placeholder="新增待办" disabled={pending} />
        <button type="submit" disabled={pending}>
          {pending ? '提交中…' : '添加'}
        </button>
      </form>

      <ul>
        {optimisticTodos.map((todo) => (
          <li key={todo.id}>
            <label>
              <input
                type="checkbox"
                checked={todo.done}
                onChange={() =>
                  startTransition(async () => {
                    mutate({ type: 'toggle', id: todo.id });
                    await toggleTodo(todo.id);
                  })
                }
              />
              <span style={{ textDecoration: todo.done ? 'line-through' : 'none' }}>
                {todo.text}
              </span>
            </label>
            <button
              onClick={() =>
                startTransition(async () => {
                  mutate({ type: 'delete', id: todo.id });
                  await deleteTodo(todo.id);
                })
              }
            >
              删除
            </button>
          </li>
        ))}
      </ul>
    </>
  );
}

::: warn 别忘了错误边界 乐观项失败后 React 回滚到 initialTodos（服务端重渲染后的真实数据），但回滚本身是静默的。在 todos/error.tsx 给出「操作失败，请重试」的兜底，或在 transition 外层 try/catch 设错误提示，避免用户误判。 :::

最佳实践清单 ​

  • [ ] 读路径打标签（cacheTag('todos')），写路径精确失效（updateTag('todos')），不滥用整路径失效
  • [ ] 每个 Action 第一步做鉴权，删除/修改一律带 ownerId 条件做所有权复核
  • [ ] 输入校验放在服务端，客户端的 required 只是体验层
  • [ ] 乐观更新只用于低风险写操作，并配齐失败回滚提示
  • [ ] Action 返回值只包含 UI 需要的形状，不直接回传数据库整行
  • [ ] 列表页保持服务端组件，客户端 JS 只覆盖真正交互的叶子
  • [ ] 需要跳转时先失效、再 redirect，因为 redirect 之后的代码不执行

真实项目核对 ​

  • [ ] 无 JS 情况下，新增表单仍可原生 POST 提交（服务端组件内的表单成立）
  • [ ] 断网或 Action 报错时，乐观 UI 能回滚且有错误提示
  • [ ] 两个标签页连续操作，后一次提交能看到前一次写入的数据（updateTag 语义）
  • [ ] 直接对 Action 路径发伪造 POST（无会话）返回拒绝，而非 500
  • [ ] Action 体积在默认 1MB 内，或已配置 bodySizeLimit

小结 ​

  • 待办全流程的标准链路：读取侧 'use cache' + cacheTag，写侧鉴权后变更、updateTag 立即失效，单往返重渲染让用户即时看到结果
  • 服务端页面取数、客户端叶子交互、action 以 props 下发，是兼顾 JS 体积与体验的组合范式
  • 乐观更新要配齐失败回滚与错误提示，鉴权与所有权复核一个都不能省
