# EP.03 服务端组件与客户端组件

> 对应正文：[第 3 章 · 服务端与客户端组件](../chapters/03-components/basics) · 配套实验：[labs/client-interaction](../labs/client-interaction) · 源码深潜：[flight-stream](../deep-dives/flight-stream)

## 剧情回顾

- **第 1 格**：标签君把 `'use client'` 打在根布局上，整棵树进了客户端包，首屏 JS 直接涨 300KB。
- **第 2 格**：码叔画出边界：服务端组件查库与读密钥，客户端组件管状态与事件，children 可以透传。
- **第 3 格**：像素酱用组合模式实证：客户端外壳包住服务端内容，服务端部分不变成客户端。
- **第 4 格**：码叔结案：客户端组件也会 SSR；跨边界 props 必须可序列化。

## 知识点拆解

### 第 1 格 · 默认服务端

App Router 中的组件默认在服务端执行，可以直接 `await db`、使用环境变量与内部服务。代价是不能使用 `useState`、`useEffect`、事件处理器与浏览器 API。

```tsx
'use client'   // 打在根布局
↓ 整棵树进入客户端包
密钥、数据库代码被迫搬走
首屏 JS +300KB
```

### 第 2 格 · 'use client' 的边界

指令写在客户端子树的入口文件顶部，该文件及其 import 的模块进入客户端包。它不会让通过 `children` 传入的服务端组件变成客户端。

- **服务端**：查库 / 密钥 / 大段静态内容
- **客户端**：状态 / 事件 / 浏览器 API
- **children**：客户端壳可包服务端内容

- 事件、状态、生命周期、localStorage 等 → 客户端
- 查库、密钥、渲染大段内容 → 服务端

### 第 3 格 · 组合模式

客户端组件可以接收服务端组件作为 `children` 或具名 slot。这样外壳保留交互，内容仍由服务端渲染，避免把整棵数据树拖进客户端。

```tsx
// page.tsx（服务端）
<SearchBox>
  <ProductGrid products={products} />
</SearchBox>
// SearchBox 是客户端，children 仍是服务端
```

### 第 4 格 · 两次渲染与水合

客户端组件并非只在浏览器渲染：首屏会由服务端产出 HTML，浏览器收到组件代码后再水合事件。客户端导航时才只下发 RSC 负载。

> ⚠️ 客户端组件也会被 SSR 成 HTML
> ⚠️ props 必须可序列化，函数不能直接传
> ⚠️ 客户端文件 import 服务端组件 → 全变客户端

## 坑点清单

1. 为了一个交互按钮，把 `'use client'` 写在根布局或页面顶层。
2. 向客户端组件传递函数、类实例或不可序列化对象。
3. 在客户端文件里 import 服务端组件，导致整块被拉进客户端包。

## 自测 3 题（含答案）

1. 客户端组件只在浏览器渲染吗？——**不是；首屏会 SSR 成 HTML，浏览器再水合交互。**
2. 怎样让客户端外壳包住服务端内容？——**通过 `children` 或具名 slot 传入，服务端组件不会变成客户端。**
3. 服务端组件能使用 useState 吗？——**不能；需要状态或事件时，把交互下沉到客户端叶子。**
