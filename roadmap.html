🔬 源码深潜

顺着实现读源码，把章节里的心智模型落到具体函数。

源码深潜：Server Action 的一次调用链打开 next 包的 action-handler：一次 POST 怎样被认出是 action、origin 与 host 为什么必须对得上、actionId 如何找到模块、以及为什么响应不是「结果」而是一次重渲染。源码深潜：Cache Components 的编译期分析与运行时边界从一次构建报错出发，沿着 next 包的 define-env、SWC 选项、路由静态信息与 app-render 的 CacheSignal，看 Cache Components 怎样在编译期变成常量与指令重写，又怎样在运行时决定「外壳到哪结束、动态从哪里开始」。源码深潜：四层缓存在一次 fetch 里的交汇打开 next 包的 patch-fetch 与 router-reducer：没有写 cache 选项的 fetch 默认走向哪、Cache Components 下无配置 fetch 为什么直接变成动态孔洞、过期条目怎样在后台重取、以及客户端刷新时哪层失效哪层保留。源码深潜：服务端渲染的 Flight 流生成链顺着 app-render 的 renderToReadableStream 与 stream-ops 的 inlined data 流，看 RSC 载荷如何被打包成一段段 <script> 塞进首屏 HTML。源码深潜：PPR 的 postponed state 如何跨请求续传打开 next 包的 server/app-render/postponed-state：静态外壳与动态内容怎样切成两段、`<长度>:<载荷><压缩缓存>` 布局为何离不开长度前缀、解析失败为什么降级而不是崩溃。源码深潜：预取策略的分级与链接意图调度打开 next 包的 segment-cache 与 Link 实现：FetchStrategy 为什么被刻意排序、PrefetchPriority 里唯一的那档 Intent 意味着什么、悬停过的链接怎样拿到被预留的带宽。源码深潜：软导航生命周期与预取状态机从一次「地址栏先变、内容后到」的点击出发，看 segment-cache 如何用一个四态枚举描述预取、navigateImpl 如何在三种入口之间分流、未命中时怎样把一次动态请求当两次用，以及后退为什么能从另一张缓存表里瞬时恢复。源码深潜：Server Action 的请求管线与安全模型从一次部署后的 404 与一次跨站 POST 被拒说起，沿着 next 包的请求元数据、42 字符 action ID、构建密钥哈希、origin 检查与流式体积上限，看一次 Server Action 在真正调用函数之前要过几道闸门，以及这些闸门各自防住什么、防不住什么。源码深潜：Turbopack 的增量构建图与缓存失效从「第二次构建为什么快、改配置为什么又变慢」出发，看 next 包交给 Turbopack 内核的持久化缓存开关、以不可变文件为单位的缓存目录、Dev 下的 partial/restart 两条增量路径，以及 hmrHash 如何把代码变更传进 use cache 的键。源码深潜：use cache 的运行时包装与缓存条目打开 next 包的 server/use-cache：一条 'use cache' 函数编译后如何被 cache() 包装、缓存条目为何要惰性生成、cacheTag 究竟把标签存到了哪里。
