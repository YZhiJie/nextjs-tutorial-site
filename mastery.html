精通中心 ​

会写代码不等于能扛生产。这一页把「精通」拆成五个可以分别训练、分别证明的维度：

维度一句话标准典型证据
⚙️ 机制理解能预测运行时行为，而不只是复述 API源码深潜、时序图、预测-验证记录
🩺 故障诊断用最小证据收敛到根因复现脚本、事故时间线、故障树
🏗️ 架构设计在约束下做可解释的取舍ADR、边界图、策略表
📈 运营治理让系统在真实流量下持续可信性能预算、回滚演练、SLO
🛡️ 安全与合规默认不信任，最小权限，可验证威胁模型、越权清单、安全回归

每一级都要求「可观察信号 + 可提交物」，避免把「读过文档」当成能力。下面的训练台会把你的自评、练习记录、复习进度与作品集保存在本机，不上传任何数据。

Mastery Model · L1–L5

五维精通中心

机制、诊断、设计、运营、安全五个维度分别打分；每条标准都必须有可观察证据与可提交物。 所有练习数据只保存在本机 localStorage。

20%综合就绪度
自测 0 / 14（0%） 实验通过 0 / 22（0%） 去自测中心补题 →

⚙️ 机制理解

知道它为什么这样跑，而不只是知道它这样跑

从 API 表面下沉到运行时与源码：RSC 载荷、缓存键、预取调度、构建图。目标是能预测行为，而不是事后解释。

自评等级：
  • L1 · 复述概念当前

    能用自己的话区分 Server/Client Component、静态与动态渲染。

    交付物：一张手绘的概念对照表（≥5 组）。

    • 术语使用准确，不混淆 RSC 与 SSR
    • 能举出一个项目中真实存在的例子
    • 能说出至少一个常见误解
  • L2 · 最小复现

    能把概念写成可运行的最小示例，并解释每一行配置的作用。

    交付物：一个仓库内可运行的 demo 或 playground 链接。

    • 示例去掉任意一行都会失败，并能说明原因
    • 能观察到预期的网络/渲染差异
    • 能指出实验的边界条件
  • L3 · 运行时推演

    能按请求生命周期讲清数据流：从点击、预取、缓存命中到流式补丁。

    交付物：一张带时序的请求链路图 + 关键日志。

    • 能标出缓存键的构成
    • 能解释首字节与完成时间分别由哪段决定
    • 能指出客户端与服务端各自的职责边界
  • L4 · 源码定位

    能指出行为落在哪个包、哪个函数，并用行号支撑结论。

    交付物：一篇带 source 引用区间的源码深潜。

    • 引用区间可直接运行/对照，不是二手转述
    • 能区分「实现细节」与「对外契约」
    • 能说明改动的风险边界
  • L5 · 预测与证伪

    能在不运行的情况下预测行为，并设计实验证伪自己的判断。

    交付物：一份预测-验证记录（含被证伪的假设）。

    • 预测包含可测量的指标
    • 实验设计能排除至少两个替代解释
    • 记录失败假设，而不是只留成功结论
不联网、不含账号信息。

怎么用这一页 ​

  1. 先自评：在「能力雷达」里给五个维度各选一个等级，不要选「应该达到」的等级，选「现在能拿出证据」的等级。
  2. 做诊断：每次只打开一个剧本，先只看症状与证据，写下自己的假设树，再展开对照。重点是训练收敛过程，不是背答案。
  3. 做决策：架构决策卡先自己选，再看推荐结论。把「什么条件下我会推翻它」写进备注。
  4. 练评审：PR 评审先估自己能看到几个问题，再看完整结论；连续三次低分说明需要回到对应章节。
  5. 间隔复习：每天只清空到期卡片，不要一次性刷完；评分要诚实，「简单」只留给能立刻说出判据的卡片。
  6. 补证据：作品集里的每条都对应一个可提交物。没有交付物，就不算到了那一级。

与正文的关系 ​

精通中心不重复正文，而是把正文里的机制、实验与深潜组织成「可训练、可验证」的任务：

  • 机制维度的证据来自 源码深潜 与各章「源码内幕」；
  • 诊断维度对应 7 个 debug-* 实验与 排障图谱；
  • 设计维度对应每章的取舍与 学习路线图；
  • 运营与安全维度对应第 11–13 章与综合实战。

建议节奏

每周完成 1 个诊断剧本 + 1 张决策卡 + 1 次 PR 评审，并把到期卡片清空。四周后回来看雷达，等级应该由证据推动，而不是由心情推动。
