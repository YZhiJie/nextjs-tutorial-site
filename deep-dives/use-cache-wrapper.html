从一个指令说起 ​

进阶篇里我用「缓存篇」的心智模型理解 'use cache'：把一个读取包成可复用的产物。但为什么一个指令就能让服务端跳过重复计算？答案在 next/dist/server/use-cache/ 这几个文件里。本篇不写类比，直接读真实产物——片段都来自你本地已安装的 next 包，行号可核对。

阅读方式

下面带 source 的代码块，左侧是注释版摘要，展开「查看源码」可看到 node_modules/next/dist/... 的原文与行号，二者一一对应。

编译期：指令变成了调用 ​

'use cache' 不是运行时扫描字符串得到的魔法。构建阶段，编译器把带该指令的函数改写为对 cache(...) 的一次调用，而这个导出就来自本文主角模块的顶端：

text
Object.defineProperty(exports, "cache", { get: () => cache });
1

也就是你在源码里写：

ts
'use cache';

export default async function Page({ params }) {
  const { slug } = await params;
  return <Article slug={slug} />;
}

::: warn 关键点 workStore 与 workUnitStore 的分工是理解整套缓存机制的钥匙：前者描述「这是哪条路由、处于哪个渲染阶段」，后者描述「当前这段工作在什么语义下执行（预渲染？请求？缓存填充？）」。很多「缓存不生效」的报错，本质是这两个 store 的组合与预期不符。 :::

缓存条目：在惰性求值里生成 ​

未命中时由 generateCacheEntryImpl 真正调用被包装的函数。注意它并非立刻执行——先记下开始时间，再把函数交给一个惰性结果：

ts
const startTime = performance.timeOrigin + performance.now(); // 供 TTL / revalidate 计算
const resultPromise = createLazyResult(fn.bind(null, ...args)); // 推迟到 React 真正 await 时才跑

为什么要「惰性」

推迟执行是为了让 React 的 request store（同样是 ALS）在被包装函数真正跑起来时已经就位——这样函数内部的 cacheTag()、cookies() 才能读到正确上下文，日志也能被捕获后重放。

标签：cacheTag 只是挂到当前 store ​

workUnitStore.tags.push(...)   // 累积到当前工作单元

自测

同一个 'use cache' 函数里连续调用 cacheTag('a') 与 cacheTag('b')，第二次调用会发生什么？

private cache 与 Resume Data Cache ​

同一份 cache() 还要区分公开与私有：入口处 isPrivate = kind === 'private' 决定缓存去向。私有缓存（例如依赖会话的读取）通常不进 cache handler，而是落到 Resume Data Cache（RDC），随渲染结果被序列化——这正是它不该被打上公共缓存的原因。

text
kind === 'private'  → Resume Data Cache（随渲染结果序列化）；开发期另有内置内存处理器
kind === 'remote'   → 走 cache handler（可替换为 Redis / 文件等）

对照我们手写的 mini-cache ​

原理篇手写的 mini-cache 分层实验 用的是「Map + tags 索引 + expireTag」；真实实现多出来的是下面这些：

关注点mini-cache（手写）next 的 use-cache
键参数拼接字符串id + 序列化参数
参数传输直接传对象经 React Flight 编解码
失效expireTag 清索引cacheTag 登记 → revalidateTag 触发再生成

求值立即执行惰性（createLazyResult）

想动手体会「写入与失效必须成对」，可以重做 mini-cache 分层实验：先让骨架校验失败，再补全 expireTag。

小结 ​

  • 指令的落地：'use cache' 编译为对 cache(kind, id, boundArgsLength, fn, args) 的调用。
  • 两个 store：workStore 管路由与渲染阶段，workUnitStore 管当前工作语义，缓存读写都挂在后者上。
  • 缓存条目惰性生成：先记 startTime，再用 createLazyResult 推迟执行，等 React await 时才真正跑。
  • 标签只是 store 上的字符串累积：cacheTag 登记、revalidateTag 触发，二者必须落在同一语义下。

读懂了包装层，下一篇换个方向：看这些缓存条目最终如何被序列化成 Flight 流发给浏览器——见 源码深潜：服务端渲染的 Flight 流生成链。
